# Linuxでテキストを編集・検索しよう｜nano・vi・grep・findを初心者向けに解説

Linuxサーバーを管理していると、テキストファイルを扱う機会がたくさんあります。

たとえば、

- 設定ファイルを書き換える
- ログファイルを確認する
- ファイルからエラーを探す
- 大量のファイルから目的のファイルを探す

といった操作です。

LinuxサーバーではGUIを使わず、ターミナルだけで作業することも珍しくありません。

そのため、

**「コマンドだけでファイルを編集・検索できる」**

ことは非常に重要です。

今回は、

- `nano`
- `vi` / `vim`
- `grep`
- `find`
- `head`
- `tail`
- パイプ `|`
- リダイレクト `>` `>>`

などを使いながら、Linuxでテキストを扱う基本を学びます。

## Linuxでは設定ファイルを編集することが多い

Linuxサーバーでは、多くの設定がテキストファイルとして保存されています。

たとえば、

```text
/etc
├── ssh
├── systemd
└── その他の設定ファイル
```

のように、`/etc`配下にはさまざまな設定ファイルがあります。

Minecraftサーバーでも、

```text
server.properties
```

という設定ファイルを編集します。

たとえば、

```text
motd=A Minecraft Server
max-players=20
server-port=25565
```

といった設定があります。

つまりLinuxサーバーを管理するうえでは、

**「設定ファイルを開いて、編集して、保存する」**

という操作が必要になります。

## テキストエディタとは？

テキストファイルを編集するためのソフトウェアを**テキストエディタ**と呼びます。

Linuxでは、

- nano
- vi
- vim

などがよく利用されます。

イメージとしては、

```text
設定ファイル
    ↓
テキストエディタで開く
    ↓
内容を変更
    ↓
保存
```

という流れです。

## nanoとは？

**nano**は、ターミナル上で利用できる比較的シンプルなテキストエディタです。

初心者でも操作を理解しやすいため、Linuxを学び始めた段階では扱いやすいエディタです。

ファイルを開く基本形は、

```bash
nano ファイル名
```

です。

たとえば、

```bash
nano sample.txt
```

とすると、`sample.txt`をnanoで開けます。

ファイルが存在しない場合は、新しいファイルとして作成できます。

## nanoで文字を書いてみよう

まず、

```bash
nano honey.txt
```

を実行してみます。

nanoが起動したら、

```text
Hello Linux!
```

などと入力してみましょう。

nanoでは基本的に、そのまま文字を入力できます。

編集できたら保存します。

## nanoで保存する

nanoでは、

```text
Ctrl + O
```

で保存できます。

`O`は「Write Out」の操作です。

保存するファイル名を確認したら`Enter`を押します。

その後、

```text
Ctrl + X
```

でnanoを終了できます。

まずは、

```text
Ctrl + O
→ 保存

Ctrl + X
→ 終了
```

を覚えておけば十分です。

## viとは？

Linuxでは**vi**というテキストエディタもよく利用されます。

```bash
vi sample.txt
```

のように起動します。

また、viを拡張した**Vim（Vi IMproved）**も広く利用されています。

環境によっては、

```bash
vim sample.txt
```

として利用できます。

viはnanoと比べると最初は少し操作が独特です。

その理由が**モード**です。

## viにはモードがある

viでは、主に、

- ノーマルモード
- インサートモード
- コマンドラインモード

を切り替えながら操作します。

イメージすると、

```text
ノーマルモード
     ↓ i
インサートモード
     ↓ Esc
ノーマルモード
     ↓ :
コマンドラインモード
```

となります。

この仕組みを知らずにviを開くと、

**「文字が入力できない！」**

となりやすいので注意しましょう。

## viで文字を入力する

まずファイルを開きます。

```bash
vi sample.txt
```

起動直後は基本的にノーマルモードです。

文字を入力するには、

```text
i
```

を押します。

すると**インサートモード**になり、文字を入力できます。

たとえば、

```text
Hello Linux!
```

と入力します。

## viで保存して終了する

編集が終わったら、

```text
Esc
```

を押してノーマルモードへ戻ります。

その後、

```text
:wq
```

と入力して`Enter`を押します。

これは、

```text
w
→ write（保存）

q
→ quit（終了）
```

という意味です。

つまり、

```text
:wq
→ 保存して終了
```

です。

保存せず終了したい場合は、

```text
:q!
```

を利用できます。

最初は、

```text
i
→ 編集開始

Esc
→ ノーマルモード

:wq
→ 保存して終了

:q!
→ 変更を保存せず終了
```

の4つを覚えておけば十分です。

## nanoとviはどちらを使えばいい？

初心者の場合、まずnanoから始めても問題ありません。

| エディタ | 特徴 |
|---|---|
| nano | 操作が比較的分かりやすい |
| vi / vim | 操作に慣れが必要だが高機能 |

Linuxサーバーではvi系エディタを利用する場面も多いため、最低限、

```text
i
Esc
:wq
:q!
```

くらいは覚えておくと便利です。

## catでファイルの内容を確認する

以前の記事で登場した`cat`を使えば、ファイルの内容を表示できます。

```bash
cat sample.txt
```

短いファイルなら、これだけで内容を簡単に確認できます。

ただしログなどの大きなファイルでは、すべて表示すると見づらくなることがあります。

そこで`head`や`tail`を利用します。

## head：ファイルの先頭を見る

ファイルの先頭部分を確認するときは、

```bash
head ファイル名
```

を利用します。

たとえば、

```bash
head sample.txt
```

です。

表示する行数を指定することもできます。

```bash
head -n 5 sample.txt
```

とすると、先頭5行を表示できます。

## tail：ファイルの末尾を見る

ファイルの最後の部分を確認するときは、

```bash
tail ファイル名
```

を利用します。

たとえば、

```bash
tail server.log
```

です。

ログファイルでは、新しい情報がファイルの末尾へ追加されることが多いため、`tail`は非常によく利用されます。

## tail -f：ログをリアルタイムで見る

ログ確認で特に便利なのが、

```bash
tail -f ファイル名
```

です。

たとえば、

```bash
tail -f server.log
```

とすると、新しくログが追加されるたびに画面へ表示されます。

イメージすると、

```text
server.log

起動しました
ユーザーが接続しました
処理を開始しました
      ↓
新しいログが追加
      ↓
画面にも表示
```

という動きです。

終了するときは、

```text
Ctrl + C
```

を押します。

サーバーの動作を確認しながらログを見るときに便利なコマンドです。

## grep：文字列を検索する

大量のログから特定の文字を探したい場合、すべてを目で確認するのは大変です。

そこで利用するのが**grep**です。

基本形は、

```bash
grep "検索文字列" ファイル名
```

です。

たとえば、

```bash
grep "ERROR" server.log
```

とすると、`ERROR`を含む行を探せます。

イメージすると、

```text
INFO Server started
INFO User connected
ERROR Connection failed
INFO Retry
ERROR Timeout
```

というログから、

```bash
grep "ERROR" server.log
```

を実行すると、

```text
ERROR Connection failed
ERROR Timeout
```

のように必要な行だけを取り出せます。

## 大文字・小文字を区別せず検索する

通常、文字列検索では大文字・小文字の違いが影響します。

たとえば、

```text
ERROR
error
Error
```

をまとめて検索したい場合には、

```bash
grep -i "error" server.log
```

のように`-i`を利用できます。

`-i`を指定すると、大文字・小文字を区別せず検索できます。

## 行番号も表示する

どの行に文字列が存在するか確認したい場合は、

```bash
grep -n "ERROR" server.log
```

とします。

すると、

```text
15:ERROR Connection failed
42:ERROR Timeout
```

のように行番号付きで表示できます。

## パイプとは？

これまでの記事でも、

```bash
ps aux | grep java
```

や、

```bash
ss -tln | grep ':22'
```

といったコマンドが登場しました。

この、

```text
|
```

を**パイプ（Pipe）**と呼びます。

パイプは、

**左側のコマンドの出力を右側のコマンドへ渡す**

ために利用します。

たとえば、

```bash
ps aux | grep java
```

なら、

```text
ps aux
↓
すべてのプロセスを表示
↓
|
↓
grep java
↓
javaを含む行だけ表示
```

という処理になります。

複数の小さなコマンドを組み合わせられるのが、Linuxの便利なところです。

## find：ファイルやディレクトリを探す

`grep`は主に**ファイルの中身**を検索するために使います。

一方、

**「ファイルそのものがどこにあるか分からない」**

という場合には`find`が便利です。

基本形の一例は、

```bash
find 検索開始場所 -name "ファイル名"
```

です。

たとえば現在のディレクトリ以下から、

```text
server.properties
```

を探したい場合、

```bash
find . -name "server.properties"
```

とできます。

ここで`.`は以前学んだ**カレントディレクトリ**です。

つまり、

```text
.
↓
現在いる場所から

-name "server.properties"
↓
この名前のファイルを探す
```

という意味です。

## Linux全体から探す場合

ルートディレクトリから検索する場合は、

```bash
find / -name "server.properties"
```

とできます。

ただし、システム全体を検索すると時間がかかったり、アクセス権限がないディレクトリでエラーが表示されたりすることがあります。

そのため、できるだけ、

```bash
find /opt -name "server.properties"
```

など、検索範囲を絞ると効率的です。

## grepとfindの違い

ここは覚えておきましょう。

```text
grep
→ ファイルの中身を探す

find
→ ファイルやディレクトリそのものを探す
```

たとえば、

**「server.propertiesはどこ？」**

なら、

```bash
find /opt -name "server.properties"
```

です。

**「ログの中にERRORという文字はある？」**

なら、

```bash
grep "ERROR" server.log
```

です。

## リダイレクトとは？

Linuxでは、コマンドの実行結果をファイルへ保存することもできます。

そこで利用するのが**リダイレクト（Redirection）**です。

代表的なのが、

```text
>
```

と、

```text
>>
```

です。

## >：ファイルへ出力する

たとえば、

```bash
echo "Hello Linux" > sample.txt
```

とすると、

```text
Hello Linux
```

という内容が`sample.txt`へ書き込まれます。

イメージすると、

```text
echoの出力
     ↓
     >
     ↓
sample.txt
```

です。

ただし、`>`を使って既存ファイルへ出力すると、基本的に元の内容は上書きされます。

ここは注意しましょう。

## >>：ファイルへ追記する

既存の内容を残したまま追加したい場合は、

```text
>>
```

を利用します。

たとえば、

```bash
echo "Hello Linux" > sample.txt
```

のあとに、

```bash
echo "Hello Server" >> sample.txt
```

を実行します。

すると、

```text
Hello Linux
Hello Server
```

となります。

つまり、

```text
>
→ 上書き

>>
→ 追記
```

です。

この違いは重要です。

## コマンドを組み合わせてみよう

Linuxでは、これまで学んだコマンドを組み合わせることで、より便利な操作ができます。

たとえば、

```bash
ps aux | grep java
```

なら、

**Javaのプロセスを探す**

ことができます。

```bash
ss -tln | grep 25565
```

なら、

**25565番ポートを探す**

ことができます。

```bash
grep "ERROR" server.log > error.log
```

なら、

**ERRORを含む行だけをerror.logへ保存する**

ことができます。

このように、

```text
コマンド
   ↓
パイプ
   ↓
別のコマンド
   ↓
リダイレクト
   ↓
ファイル
```

と組み合わせられます。

## Minecraftサーバーではどう使う？

Minecraftサーバーを構築すると、今回のコマンドをかなり利用します。

たとえば、

```text
/opt/minecraft
├── server.jar
├── server.properties
├── world
└── logs
```

という構成だったとします。

Minecraftの設定を変更したい場合は、

```bash
nano /opt/minecraft/server.properties
```

などで設定ファイルを開けます。

たとえば、

```text
motd=Huney Minecraft Server
max-players=10
server-port=25565
```

などの設定を編集します。

## Minecraftのログを確認する

Minecraftサーバーではログも重要です。

たとえばログディレクトリへ移動します。

```bash
cd /opt/minecraft/logs
```

ファイルを確認します。

```bash
ls
```

最新ログが`latest.log`なら、

```bash
tail latest.log
```

で末尾を確認できます。

リアルタイムで確認したい場合は、

```bash
tail -f latest.log
```

です。

## Minecraftのエラーを探す

ログが大量にある場合、

```bash
grep -i "error" latest.log
```

のように検索できます。

さらに、

```bash
grep -i "error" latest.log > error.log
```

とすれば、エラーを含む行を別のファイルへ保存することもできます。

ここまでできると、

```text
Minecraftで問題発生
        ↓
ログを確認
        ↓
grepでエラーを探す
        ↓
原因を調査
```

という、実際のサーバートラブルシューティングに近い操作ができます。

## 設定ファイルを変更したらどうする？

設定ファイルは、書き換えただけでは動作中のサービスへ反映されないことがあります。

たとえば一般的なサービスでは、

```text
設定ファイルを編集
      ↓
保存
      ↓
サービスを再起動・再読み込み
      ↓
新しい設定を反映
```

という流れになることがあります。

以前学んだ、

```bash
sudo systemctl restart サービス名
```

などがここでつながります。

ただし、サービスによって設定の反映方法は異なるため、そのサービスに適した方法を確認して操作します。

## 設定ファイルを編集するときはバックアップも意識しよう

重要な設定ファイルを変更するときは、いきなり編集するのではなく、変更前のファイルをコピーしておく方法があります。

たとえば、

```bash
cp server.properties server.properties.bak
```

とします。

すると、

```text
server.properties
server.properties.bak
```

の2つができます。

もし編集後に問題が発生しても、元の設定を確認しやすくなります。

以前学んだ`cp`が、実際のサーバー管理でも役立ちます。

## 実際に操作してみよう

まず練習用ディレクトリを作ります。

```bash
mkdir -p ~/linux-practice/text
```

移動します。

```bash
cd ~/linux-practice/text
```

nanoでファイルを作ります。

```bash
nano sample.txt
```

次のように入力して保存してみましょう。

```text
INFO Server started
INFO User connected
ERROR Connection failed
INFO Retry
ERROR Timeout
```

保存できたら、

```bash
cat sample.txt
```

で確認します。

先頭を確認します。

```bash
head sample.txt
```

末尾を確認します。

```bash
tail sample.txt
```

ERRORだけ検索します。

```bash
grep "ERROR" sample.txt
```

行番号付きでも確認します。

```bash
grep -n "ERROR" sample.txt
```

次にファイルを探します。

```bash
find . -name "sample.txt"
```

最後に、ERRORを含む行だけ別ファイルへ保存します。

```bash
grep "ERROR" sample.txt > error.txt
```

確認します。

```bash
cat error.txt
```

これで、

```text
編集
↓
表示
↓
検索
↓
ファイル探索
↓
結果を保存
```

という一連の操作を体験できます。

## まとめ

今回はLinuxでテキストを編集・検索する方法を学びました。

### この記事で覚えること

- Linuxでは設定ファイルやログをテキストとして扱うことが多い
- `nano`は初心者でも扱いやすいテキストエディタ
- viではモードを切り替えて操作する
- viでは`i`で入力、`Esc`でノーマルモードへ戻る
- `:wq`で保存して終了できる
- `:q!`で変更を保存せず終了できる
- `head`でファイルの先頭を確認できる
- `tail`でファイルの末尾を確認できる
- `tail -f`でログを継続的に確認できる
- `grep`でファイル内の文字列を検索できる
- `find`でファイルやディレクトリを探せる
- `|`でコマンドの出力を別のコマンドへ渡せる
- `>`は出力先を上書きする
- `>>`は出力先へ追記する
- 設定変更前にはバックアップを取る習慣も重要
- Minecraftでは設定ファイル編集やログ調査に利用できる

ここまで学ぶと、

**「Linuxへログインしてコマンドを実行する」**

だけでなく、

**「設定を変更して、ログを確認して、問題を調査する」**

というサーバー管理らしい操作ができるようになります。

コマンド単体ではなく、

```text
設定を編集する
↓
サービスを動かす
↓
ログを見る
↓
問題があれば検索する
```

という流れで覚えていきましょう。
