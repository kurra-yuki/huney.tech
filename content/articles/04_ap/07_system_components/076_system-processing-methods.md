# システムの処理形態とは？集中処理・分散処理・シンクライアント・VDIをやさしく解説

## はじめに

私たちが普段利用している情報システムは、さまざまなコンピュータによって動いています。

例えば、会社の勤怠管理システムを考えてみましょう。

従業員が出勤ボタンを押すと、勤務開始時刻が記録されます。

しかし、この処理はどこで行われているのでしょうか？

- 従業員が使っているパソコン？
- 社内に設置されたサーバ？
- インターネット上のクラウド？

実は、システムによって処理を行う場所や役割分担が異なります。

このような、**コンピュータに処理をどのように担当させるかという仕組み**を、システムの処理形態といいます。

今回は、代表的な2つの処理形態を学びます。

```text
システムの処理形態
│
├─ 集中処理システム
│   └─ シンクライアント端末
│
└─ 分散処理システム
    ├─ 分散処理システムの形態
    │   ├─ 水平分散
    │   └─ 垂直分散
    │
    └─ VDI
```

それぞれの仕組みを理解していきましょう。

---

# 1. 集中処理システム

## 1-1. 集中処理システムとは

**集中処理システム（Centralized Processing System）**とは、

**1台の中央コンピュータなどに処理を集中させる方式**です。

例えば、会社に高性能なサーバが1台あり、従業員が端末からそのサーバを利用する場合を考えてみましょう。

```text
        集中処理システム

          ┌──────────┐
          │ 中央サーバ │
          │            │
          │ データ管理 │
          │ 業務処理   │
          │ 計算処理   │
          └─────┬────┘
                │
       ┌────────┼────────┐
       │        │        │
    ┌──┴──┐  ┌──┴──┐  ┌──┴──┐
    │端末A│  │端末B│  │端末C│
    └─────┘  └─────┘  └─────┘
```

端末から操作を行いますが、主な処理は中央サーバが担当します。

つまり、

> **複数の端末から利用していても、処理の中心は中央コンピュータにある**

という仕組みです。

---

## 1-2. 集中処理システムのメリット

### ① データを一元管理できる

データを中央サーバで管理できるため、バックアップやアクセス制御などを統一しやすくなります。

例えば、

```text
端末A ─┐
端末B ─┼── 中央サーバ
端末C ─┘       │
             データ
```

という構成であれば、端末ごとに重要なデータを管理する必要性を減らせます。

### ② 管理・運用を統一しやすい

ソフトウェアの更新や設定変更を中央側で実施できるため、管理を集約しやすくなります。

### ③ セキュリティ対策を集約しやすい

重要なデータを中央側に保存する構成であれば、端末へのデータ保存を制限できます。

ただし、中央サーバの保護が不十分だと、影響が広範囲に及ぶ可能性があります。

---

## 1-3. 集中処理システムのデメリット

### ① 中央サーバに負荷が集中する

利用者が増えると、中央サーバに処理が集中します。

```text
端末A ─┐
端末B ─┤
端末C ─┼── 中央サーバ
端末D ─┤      ↑
端末E ─┘    負荷集中
```

サーバの処理能力が不足すると、システム全体の動作が遅くなる可能性があります。

### ② 中央サーバの障害による影響が大きい

中央サーバが停止すると、多くの利用者がシステムを利用できなくなる可能性があります。

これを防ぐためには、サーバの冗長化などの対策が重要です。

### ③ ネットワークへの依存度が高い

中央サーバとの通信が必要な構成では、ネットワーク障害によってサービスを利用できなくなることがあります。

---

# 2. シンクライアント端末

## 2-1. シンクライアントとは

**シンクライアント（Thin Client）**とは、

**端末側の機能を必要最小限に抑え、主な処理やデータ管理をサーバ側に任せる考え方**です。

Thinは「薄い」という意味です。

つまり、

> **端末をシンプルにして、サーバ側に処理を任せる**

という仕組みです。

---

## 2-2. シンクライアントの仕組み

例えば、会社で利用するパソコンを考えてみましょう。

通常のパソコンでは、アプリケーションの実行やデータ保存などを端末側で行うことがあります。

一方、シンクライアントでは、主な処理をサーバ側で行います。

```text
       シンクライアント環境

  ┌──────────────────┐
  │      サーバ       │
  │                  │
  │ アプリケーション │
  │ データ管理       │
  │ 業務処理         │
  └────────┬─────────┘
           │
       ネットワーク
           │
  ┌────────┴─────────┐
  │ シンクライアント │
  │                  │
  │ 画面表示         │
  │ キーボード入力   │
  │ マウス操作       │
  └──────────────────┘
```

利用者は手元の端末を操作しますが、主な処理はサーバ側で実行されます。

端末側は、画面表示や入力操作などを中心に担当します。

---

## 2-3. シンクライアントのメリット

### ① 情報漏えいリスクを低減できる

重要なデータを端末側に保存しない構成にすれば、端末の紛失や盗難による情報漏えいリスクを減らせます。

ただし、画面の撮影や認証情報の漏えいなど、別のリスクは残ります。

### ② 端末管理を効率化しやすい

アプリケーションやデータを中央側で管理することで、端末ごとの管理負担を軽減できます。

### ③ 端末に高い処理能力を要求しにくい

主な処理をサーバ側で実行する方式では、端末側に高性能なCPUや大容量ストレージを必要としない場合があります。

---

## 2-4. シンクライアントのデメリット

### ① ネットワークに依存する

サーバとの通信が必要なため、ネットワーク障害が発生すると業務に影響します。

### ② サーバ側に負荷が集中する

多くの利用者が同時に利用すると、サーバ側に高い処理能力が求められます。

### ③ 導入・運用コストが発生する

サーバ設備、ライセンス、ネットワークなどの費用が必要になることがあります。

端末が安価になっても、必ずしもシステム全体のコストが下がるとは限りません。

---

## 2-5. シンクライアントと通常のPCの違い

| 比較項目 | 通常のPC | シンクライアント |
|---|---|---|
| 主な処理場所 | 端末側 | サーバ側 |
| データ保存 | 端末側にも保存可能 | サーバ側へ集約する構成が多い |
| 端末性能 | 用途に応じた性能が必要 | 比較的低い性能でも利用可能な場合がある |
| 管理 | 端末ごとの管理が必要になりやすい | 中央管理しやすい |
| ネットワーク | オフライン利用できる場合もある | 通信への依存度が高い |

🍯 **シンクライアントは「手元の端末は操作役、重い仕事はサーバ役」と考えると覚えやすいです。**

---

# 3. 分散処理システム

## 3-1. 分散処理システムとは

**分散処理システム（Distributed Processing System）**とは、

**複数のコンピュータに処理を分担させる方式**です。

集中処理システムでは中央コンピュータに処理を集めていました。

一方、分散処理システムでは、複数のコンピュータが役割を分担します。

```text
         分散処理システム

        ┌──────────┐
        │ 利用者   │
        └────┬─────┘
             │
     ┌───────┼───────┐
     │       │       │
┌────┴──┐ ┌──┴────┐ ┌┴──────┐
│サーバA│ │サーバB│ │サーバC│
│処理A  │ │処理B  │ │処理C  │
└───────┘ └───────┘ └───────┘
```

例えば、Webサービスでは、

- Webサーバ
- アプリケーションサーバ
- データベースサーバ

などに役割を分担させることがあります。

---

## 3-2. 分散処理システムのメリット

### ① 負荷を分散できる

複数のコンピュータに処理を分担させることで、1台への負荷集中を減らせます。

### ② システムを拡張しやすい

処理能力が不足した場合、構成によってはサーバを追加して性能を向上できます。

### ③ 障害の影響を限定できる場合がある

適切に冗長化された構成では、1台の障害が発生しても、ほかのサーバで処理を継続できる場合があります。

ただし、**分散処理にしただけで自動的に高い信頼性が得られるわけではありません。**

---

## 3-3. 分散処理システムのデメリット

### ① 管理が複雑になる

複数のコンピュータを管理するため、構成管理や障害対応が複雑になる場合があります。

### ② 通信処理が必要になる

コンピュータ間でデータをやり取りするため、ネットワークの性能や信頼性が重要になります。

### ③ データの整合性を考える必要がある

複数のコンピュータでデータを扱う場合、同じデータを矛盾なく管理する仕組みが必要になることがあります。

---

# 4. 分散処理システムの形態

分散処理システムには、処理の分担方法によってさまざまな形態があります。

ここでは代表的な、

- 水平分散
- 垂直分散

を紹介します。

## 4-1. 水平分散

**水平分散（Horizontal Distribution）**とは、

**同じ種類の処理を複数のコンピュータで分担する方式**です。

例えば、Webサイトへのアクセスが増えた場合を考えてみましょう。

```text
            利用者
              │
              ▼
        ┌──────────┐
        │負荷分散装置│
        └────┬─────┘
             │
    ┌────────┼────────┐
    │        │        │
    ▼        ▼        ▼
┌──────┐ ┌──────┐ ┌──────┐
│Web A │ │Web B │ │Web C │
└──────┘ └──────┘ └──────┘
```

Webサーバを3台用意し、アクセスを分散しています。

各サーバは基本的に同じ種類の処理を担当します。

### 水平分散の特徴

- 同じ種類の処理を複数台で分担する
- サーバ追加によって処理能力を拡張しやすい
- 負荷分散と組み合わせることが多い

例えば、アクセス数の増加に応じてWebサーバを追加する構成が該当します。

---

## 4-2. 垂直分散

**垂直分散（Vertical Distribution）**とは、

**処理の種類や役割ごとにコンピュータを分担させる方式**です。

例えば、Webシステムを考えてみましょう。

```text
           利用者
             │
             ▼
      ┌──────────┐
      │ Webサーバ │
      │ 画面配信  │
      └────┬─────┘
           │
           ▼
      ┌──────────┐
      │ APサーバ  │
      │ 業務処理  │
      └────┬─────┘
           │
           ▼
      ┌──────────┐
      │ DBサーバ  │
      │ データ管理│
      └──────────┘
```

このように、

```text
Webサーバ
→ Webコンテンツの配信

APサーバ
→ アプリケーションの処理

DBサーバ
→ データの管理
```

というように役割を分担します。

### 垂直分散の特徴

- 機能や役割ごとに処理を分担する
- 各サーバの役割を明確にしやすい
- システム全体の構成が複雑になる場合がある

---

## 4-3. 水平分散と垂直分散の違い

| 比較項目 | 水平分散 | 垂直分散 |
|---|---|---|
| 分散の考え方 | 同じ種類の処理を分担 | 異なる種類の処理を分担 |
| 例 | Webサーバを複数台設置 | Web・AP・DBを分離 |
| 主な目的 | 負荷分散・処理能力の拡張 | 機能ごとの役割分担 |
| 特徴 | 同種のサーバが並ぶ | 異なる役割のサーバが連携 |

### 🍯 覚え方

```text
水平分散
→ 同じ仕事をみんなで分担

垂直分散
→ 違う仕事を役割分担
```

例えば、はちみつ屋さんなら、

**水平分散**

```text
注文受付A
注文受付B
注文受付C
```

同じ仕事を複数人で分担します。

**垂直分散**

```text
注文受付
   ↓
はちみつ製造
   ↓
梱包
   ↓
発送
```

異なる仕事を役割ごとに分担します。

# 5. VDI

## 5-1. VDIとは

**VDI（Virtual Desktop Infrastructure）**とは、

**サーバ側に仮想デスクトップ環境を用意し、利用者がネットワーク経由でそのデスクトップを利用する仕組み**です。

日本語では、**仮想デスクトップ基盤**と呼ばれます。

---

## 5-2. VDIの仕組み

通常のPCでは、OSやアプリケーションが手元の端末で動作します。

一方、VDIでは、サーバ側で仮想デスクトップを動作させます。

```text
              VDI環境

      ┌────────────────┐
      │    VDI基盤     │
      │                │
      │ ┌────────────┐ │
      │ │仮想PC A    │ │
      │ │OS・アプリ  │ │
      │ └────────────┘ │
      │                │
      │ ┌────────────┐ │
      │ │仮想PC B    │ │
      │ │OS・アプリ  │ │
      │ └────────────┘ │
      │                │
      │ ┌────────────┐ │
      │ │仮想PC C    │ │
      │ │OS・アプリ  │ │
      │ └────────────┘ │
      └────────┬───────┘
               │
          ネットワーク
               │
      ┌────────┼────────┐
      │        │        │
    端末A    端末B    端末C
```

利用者は手元の端末から仮想PCへ接続します。

キーボードやマウスで操作した内容は仮想PCへ送られ、処理結果が画面として端末に表示されます。

---

## 5-3. VDIのメリット

### ① デスクトップ環境を集中管理できる

OSやアプリケーションなどをサーバ側で管理できるため、管理を集約しやすくなります。

### ② 端末へのデータ保存を制限できる

業務データをサーバ側に保存する構成にすることで、端末の紛失・盗難による情報漏えいリスクを低減できます。

### ③ 場所に依存しにくい働き方に対応できる

適切なネットワークと認証環境があれば、オフィス以外の場所からも仮想デスクトップへ接続できます。

---

## 5-4. VDIのデメリット

### ① サーバ側に高い処理能力が必要

複数の仮想デスクトップを動作させるため、CPU・メモリ・ストレージなどの資源が必要です。

### ② ネットワーク品質の影響を受ける

通信の遅延や帯域不足によって、画面操作が遅く感じられることがあります。

### ③ 導入・運用コストがかかる

仮想化基盤、ストレージ、ライセンスなどの費用が必要になります。

---

# 6. シンクライアントとVDIの違い

ここは特に混同しやすいポイントです。

結論からいうと、

> **シンクライアントは端末側の機能を最小限にする考え方、VDIはサーバ側に仮想デスクトップを用意する仕組み**

です。

つまり、同じものではありません。

## 6-1. シンクライアント

シンクライアントは、主な処理をサーバ側へ集約する端末利用の考え方です。

```text
シンクライアント端末
        │
        ▼
サーバ側で処理
```

## 6-2. VDI

VDIは、サーバ側に仮想PCを用意します。

```text
利用者の端末
      │
      ▼
VDI基盤
      │
      ▼
仮想PC
      │
      ▼
OS・アプリを実行
```

そして、このVDIへ接続する端末として、シンクライアント端末を利用することがあります。

```text
シンクライアント端末
         │
         ▼
      VDI基盤
         │
         ▼
    仮想デスクトップ
```

ただし、VDIへの接続には通常のPCなどを利用することもできます。

また、シンクライアント方式が必ずVDIを利用するわけでもありません。

---

## 6-3. 比較表

| 比較項目 | シンクライアント | VDI |
|---|---|---|
| 分類 | 端末利用方式・考え方 | 仮想デスクトップ基盤 |
| 主な特徴 | 端末側の機能を抑える | サーバ側で仮想デスクトップを動かす |
| 主な処理場所 | サーバ側 | 仮想デスクトップ側 |
| 利用端末 | シンクライアント端末など | シンクライアント端末、通常PCなど |
| 関係 | VDIと組み合わせられる | シンクライアント方式の実現方法の一つ |

🍯 **「シンクライアント＝手元の端末をシンプルにする」「VDI＝サーバの中に仮想PCを用意する」と覚えましょう。**

---

# 7. 集中処理と分散処理を比較しよう

最後に、今回の中心テーマである2つの処理形態を比較します。

| 比較項目 | 集中処理システム | 分散処理システム |
|---|---|---|
| 処理場所 | 中央コンピュータに集中 | 複数のコンピュータに分散 |
| データ管理 | 一元管理しやすい | 分散したデータの管理が必要な場合がある |
| 負荷 | 中央に集中しやすい | 分散できる |
| 障害の影響 | 中央の障害が広範囲に影響しやすい | 構成次第で影響を限定できる |
| 管理 | 集中管理しやすい | 構成が複雑になりやすい |
| 拡張性 | 中央の処理能力に依存しやすい | サーバ追加などで拡張しやすい場合がある |

なお、実際のシステムでは、集中処理と分散処理の考え方を組み合わせることもあります。

例えばVDIでは、

- 利用者のデスクトップ環境をデータセンターへ集約する
- そのVDI基盤を複数の物理サーバで構成する

ということがあります。

この場合、**利用者から見た処理の集中**と、**基盤内部での処理の分散**が共存しています。

したがって、VDIだから必ず「1台の中央サーバだけで処理する」とは限りません。

# まとめ

## この記事で覚えること

- **集中処理システム**は、中央コンピュータに処理を集中させる方式
- 集中処理はデータや運用を一元管理しやすい一方、中央への負荷集中や障害の影響に注意が必要
- **シンクライアント**は、端末側の機能を抑えて主な処理をサーバ側へ任せる考え方
- **分散処理システム**は、複数のコンピュータで処理を分担する方式
- **水平分散**は、同じ種類の処理を複数のコンピュータで分担する
- **垂直分散**は、異なる種類の処理を役割ごとに分担する
- 分散処理は負荷分散や拡張性に優れる場合があるが、管理や通信が複雑になることもある
- **VDI**は、サーバ側に仮想デスクトップを用意し、ネットワーク経由で利用する仕組み
- シンクライアントとVDIは同じものではなく、組み合わせて利用できる
- 集中処理と分散処理は、実際のシステム内で共存する場合もある

---

## 🍯 はちみつメモ

> **集中処理は「1か所に仕事を集める」、分散処理は「複数のコンピュータで仕事を分担する」。**
>
> 分散処理の中でも、**水平分散は「同じ仕事を複数台で分担」、垂直分散は「異なる仕事を役割分担」**と覚えよう！
>
> そして、シンクライアントとVDIは混同しないこと。**シンクライアントは端末をシンプルにする考え方、VDIはサーバ側に仮想デスクトップを用意する仕組み**だよ！
