# 情報システム戦略とは？EA・ITガバナンス・IT投資評価・業務改善・SOAをやさしく解説

## はじめに

企業では、さまざまな業務にITシステムが利用されています。

例えば、次のようなシステムです。

- 売上を管理する販売管理システム
- 商品の在庫を管理する在庫管理システム
- 従業員の給与を計算する給与管理システム
- 顧客情報を管理する顧客管理システム
- 経営状況を分析する情報分析システム

これらのシステムは、企業の業務を効率化するために欠かせません。

しかし、ITシステムを導入すれば、必ず企業の経営が改善するわけではありません。

例えば、販売部門と在庫管理部門が別々のシステムを導入した場合、同じ商品情報を二重に登録しなければならないことがあります。

また、業務の進め方を見直さずにシステムだけを導入すると、かえって作業が複雑になる場合もあります。

そこで重要になるのが、**情報システム戦略**です。

情報システム戦略では、企業の経営目標を達成するために、ITをどのように活用するのかを考えます。

今回は、次の内容を学びます。

1. 情報システム戦略の基本
2. 業務モデル・ビジネスプロセス・データモデル
3. EAによる全体最適化
4. ITガバナンスと組織体制
5. IT投資戦略と投資評価
6. 業務プロセスの改善
7. ソリューションサービス

---

# 1. 情報システム戦略とは

## 1-1. 情報システム戦略の基本

**情報システム戦略（Information Systems Strategy）**とは、企業の経営戦略を実現するために、情報システムをどのように活用するかを定める方針や計画です。

企業には、売上の向上やコスト削減、顧客満足度の向上など、さまざまな経営目標があります。

情報システム戦略では、これらの目標を達成するためにITを活用します。

例えば、ある企業が次の経営目標を掲げたとします。

**「商品の売上を20%増やしたい」**

この目標に対して、次のようなIT活用を検討できます。

- ECサイトを開設する
- 顧客の購買履歴を分析する
- 在庫管理を自動化する
- 顧客管理システムを導入する

このように、経営目標からITの活用方法を考えることが重要です。

---

## 1-2. 経営戦略と情報システム戦略の関係

情報システム戦略は、経営戦略と切り離して考えるものではありません。

基本的には、次の関係があります。

```text
┌────────────────────┐
│ 経営理念・経営目標   │
└──────────┬─────────┘
           │
           ▼
┌────────────────────┐
│ 経営戦略             │
│ 何を実現するのか     │
└──────────┬─────────┘
           │
           ▼
┌────────────────────┐
│ 情報システム戦略     │
│ ITをどう活用するか   │
└──────────┬─────────┘
           │
           ▼
┌────────────────────┐
│ システム企画・導入   │
└──────────┬─────────┘
           │
           ▼
┌────────────────────┐
│ 運用・評価・改善     │
└────────────────────┘
```

ただし、実際にはITによって新しいビジネスモデルが生まれ、経営戦略そのものが変化する場合もあります。

そのため、経営戦略と情報システム戦略は、相互に影響し合う関係にあります。

---

## 1-3. 情報戦略とは

**情報戦略（Information Strategy）**とは、企業が保有する情報やデータを、経営や業務にどのように活用するかを定める方針です。

情報システム戦略がITシステムの活用に重点を置くのに対し、情報戦略では情報そのものの価値に注目します。

例えば、顧客の購買履歴を収集している企業を考えてみましょう。

情報を保存するだけでは、十分に活用できているとはいえません。

そこで、

- どのような情報を収集するか
- 情報をどこに保存するか
- 誰が情報を利用できるか
- どのように分析するか
- 分析結果を経営判断にどう活用するか

を考えます。

これが情報戦略です。

### 🍯 はちみつ屋さんで例えると

はちみつ屋さんが、顧客の購入履歴を記録しているとします。

```text
顧客の購入履歴
      │
      ▼
売れ筋商品の分析
      │
      ▼
人気商品の把握
      │
      ▼
仕入れ数量の調整
      │
      ▼
売上・利益の改善
```

このように、情報を経営に役立てることが情報戦略の目的です。

---

# 2. 業務モデル・ビジネスプロセス・データモデル

情報システム戦略を立案するときは、企業の業務を正しく理解する必要があります。

そのために利用するのが、業務モデルやデータモデルです。

## 2-1. 業務モデルとは

**業務モデル（Business Model of Operations）**とは、企業の業務内容や業務間の関係、役割分担などを整理して表現したものです。

例えば、商品を販売する企業では、次のような業務があります。

```text
商品を仕入れる
      │
      ▼
在庫を管理する
      │
      ▼
注文を受け付ける
      │
      ▼
商品を発送する
      │
      ▼
代金を回収する
```

このように、企業の業務を整理すると、業務全体の流れや問題点を把握しやすくなります。

業務モデルは、システム化する範囲を検討するときにも役立ちます。

---

## 2-2. ビジネスプロセスとは

**ビジネスプロセス（Business Process）**とは、企業が特定の目的を達成するために実行する、一連の業務活動の流れです。

例えば、商品の注文を受けてから発送するまでの流れを考えてみましょう。

```text
注文受付
   │
   ▼
在庫確認
   │
   ▼
支払確認
   │
   ▼
出荷指示
   │
   ▼
商品発送
```

この一連の流れがビジネスプロセスです。

業務モデルが業務全体の構造を表すのに対し、ビジネスプロセスは、業務がどのような順番で実行されるのかに注目します。

---

## 2-3. データモデルとは

**データモデル（Data Model）**とは、システムで扱うデータの種類や構造、データ同士の関係を整理したものです。

例えば、はちみつ屋さんの販売管理システムでは、次のようなデータを扱います。

- 顧客
- 商品
- 注文
- 注文明細

これらの関係を考えてみましょう。

```text
┌──────────┐
│ 顧客     │
│ 顧客ID   │
│ 顧客名   │
└────┬─────┘
     │
     │ 注文する
     ▼
┌──────────┐
│ 注文     │
│ 注文ID   │
│ 顧客ID   │
└────┬─────┘
     │
     │ 含まれる
     ▼
┌──────────┐
│ 注文明細 │
│ 注文ID   │
│ 商品ID   │
│ 数量     │
└────┬─────┘
     │
     │ 対象商品
     ▼
┌──────────┐
│ 商品     │
│ 商品ID   │
│ 商品名   │
└──────────┘
```

このように、データの構造や関係を整理することで、適切なデータベース設計につなげられます。

データモデルを表現する代表的な手法には、**ER図（Entity Relationship Diagram）**があります。

---

## 2-4. 3つの違い

| 項目 | 主な目的 | 注目するもの |
|---|---|---|
| 業務モデル | 業務全体の構造を整理する | 業務・役割・関係 |
| ビジネスプロセス | 業務の流れを整理する | 作業の順序・手順 |
| データモデル | データの構造を整理する | データ・属性・関係 |

**業務モデルは「何をしているか」、ビジネスプロセスは「どう進めるか」、データモデルは「どんなデータを扱うか」**と考えると理解しやすくなります。

# 3. 全体最適化とは

## 3-1. 部分最適と全体最適

企業では、部署ごとに業務の効率化を進めることがあります。

例えば、

- 営業部門が独自の顧客管理システムを導入する
- 経理部門が独自の会計システムを導入する
- 在庫管理部門が独自の在庫管理システムを導入する

といったケースです。

各部署では便利になっても、企業全体では問題が発生する場合があります。

例えば、同じ顧客情報を複数のシステムに登録する必要があるかもしれません。

このように、一部の部署だけを最適化することを**部分最適**と呼びます。

一方、企業全体を見渡して最も効果的な仕組みを考えることを、**全体最適**と呼びます。

---

## 3-2. 全体最適化の例

### 部分最適の状態

```text
営業部門
  └─ 顧客管理システムA

経理部門
  └─ 会計システムB

在庫管理部門
  └─ 在庫管理システムC

※ データの重複や不整合が発生
```

### 全体最適化した状態

```text
          共通データ基盤
                │
      ┌─────────┼─────────┐
      │         │         │
      ▼         ▼         ▼
   営業部門   経理部門   在庫管理部門
      │         │         │
      └─────────┴─────────┘
           データを連携
```

企業全体で情報を共有することで、業務の重複やデータの不整合を減らせます。

ただし、全体最適化は、すべてのシステムを1つに統合することを意味するわけではありません。

業務の特性に応じてシステムを分離しながら、全体として整合性を確保することも重要です。

---

# 4. EAとは

## 4-1. EAの基本

**EA（Enterprise Architecture：エンタープライズアーキテクチャ）**とは、企業や組織全体の業務と情報システムを体系的に整理し、全体最適化を進めるための考え方です。

EAでは、現在の業務やシステムの状態を把握し、将来あるべき姿を設計します。

例えば、

- 同じ機能を持つシステムが複数存在していないか
- データを共有できているか
- 業務の流れに無駄がないか
- IT基盤が適切に整備されているか

といった点を確認します。

---

## 4-2. As-IsとTo-Be

EAでは、現状と将来像を比較して改善を進めます。

### As-Is

**As-Is**とは、現在の業務やシステムの状態です。

### To-Be

**To-Be**とは、将来実現したい業務やシステムの状態です。

```text
┌────────────────┐
│ As-Is         │
│ 現在の状態     │
└───────┬────────┘
        │
        ▼
┌────────────────┐
│ ギャップ分析   │
│ 課題を把握     │
└───────┬────────┘
        │
        ▼
┌────────────────┐
│ 改善計画       │
└───────┬────────┘
        │
        ▼
┌────────────────┐
│ To-Be         │
│ 目指す状態     │
└────────────────┘
```

例えば、現在は紙で管理している申請業務を、将来的に電子申請へ移行する場合などが該当します。

---

# 5. EAの4つの体系

EAでは、組織を次の4つの観点から整理します。

1. BA：ビジネスアーキテクチャ
2. DA：データアーキテクチャ
3. AA：アプリケーションアーキテクチャ
4. TA：テクノロジアーキテクチャ

---

## 5-1. BA：ビジネスアーキテクチャ

**BA（Business Architecture）**とは、企業の業務内容や業務プロセス、組織の役割などを整理する体系です。

例えば、

- どの部署が何を担当しているか
- 業務がどのような順番で実行されるか
- どの業務に問題があるか

を整理します。

代表的な成果物には、業務フローや業務機能の一覧などがあります。

---

## 5-2. DA：データアーキテクチャ

**DA（Data Architecture）**とは、企業が利用するデータの構造や関係を整理する体系です。

例えば、

- 顧客データ
- 商品データ
- 注文データ
- 売上データ

などを整理します。

代表的な成果物には、データモデルやデータ項目の定義などがあります。

---

## 5-3. AA：アプリケーションアーキテクチャ

**AA（Application Architecture）**とは、業務を実現するためのアプリケーションやシステムの構成を整理する体系です。

例えば、

- 販売管理システム
- 在庫管理システム
- 顧客管理システム

などの機能や連携方法を整理します。

代表的な成果物には、アプリケーション構成図やシステム間連携図などがあります。

---

## 5-4. TA：テクノロジアーキテクチャ

**TA（Technology Architecture）**とは、情報システムを動作させるための技術基盤を整理する体系です。

例えば、

- サーバ
- ネットワーク
- ストレージ
- OS
- ミドルウェア
- クラウド基盤

などです。

代表的な成果物には、システム基盤構成図やネットワーク構成図などがあります。

---

## 5-5. EAの4体系の関係

```text
┌────────────────────────┐
│ BA：業務                 │
│ 何を実現するか           │
└───────────┬────────────┘
            │
            ▼
┌────────────────────────┐
│ DA：データ               │
│ どんな情報を扱うか       │
└───────────┬────────────┘
            │
            ▼
┌────────────────────────┐
│ AA：アプリケーション     │
│ どんな機能を使うか       │
└───────────┬────────────┘
            │
            ▼
┌────────────────────────┐
│ TA：技術基盤             │
│ 何の技術で動かすか       │
└────────────────────────┘
```

この図は理解しやすくするための整理です。

実際のEAでは、4つの体系を一方向に設計するだけでなく、相互の整合性を確認しながら検討します。

---

## 5-6. EAのまとめ

| 体系 | 正式名称 | 主な対象 |
|---|---|---|
| BA | Business Architecture | 業務・組織・業務プロセス |
| DA | Data Architecture | データ構造・データの関係 |
| AA | Application Architecture | アプリケーション・システム機能 |
| TA | Technology Architecture | サーバ・ネットワーク・技術基盤 |

応用情報技術者試験では、**BA・DA・AA・TAの違い**を覚えておきましょう。

# 6. ITガバナンスとは

## 6-1. ITガバナンスの基本

**ITガバナンス（IT Governance）**とは、組織がITを適切に活用し、経営目標の達成につなげるための統治の仕組みです。

企業では、多くのIT投資が行われています。

しかし、部署ごとに自由にシステムを導入すると、

- IT投資が重複する
- セキュリティ対策にばらつきが生まれる
- システムの運用コストが増加する
- 経営方針とIT投資が一致しない

といった問題が発生する場合があります。

そこで、組織全体でITに関する意思決定や管理の仕組みを整備します。

---

## 6-2. ITガバナンスの目的

ITガバナンスの主な目的には、次のようなものがあります。

### ① 経営戦略とIT戦略の整合

IT投資が経営目標の達成につながるようにします。

### ② IT投資の価値の最大化

限られた予算を効果的に活用します。

### ③ リスクの管理

情報漏えいやシステム障害などのリスクを管理します。

### ④ IT資源の適切な管理

人材・システム・データ・予算などを適切に配分します。

### ⑤ 成果の評価

IT投資やIT施策の効果を評価し、改善につなげます。

---

# 7. ITガバナンスと組織体制

## 7-1. ITガバナンスを支える組織

ITガバナンスを実現するためには、責任と権限を明確にする必要があります。

例えば、次のような組織体制が考えられます。

```text
┌────────────────────┐
│ 経営層               │
│ IT方針・投資判断     │
└──────────┬─────────┘
           │
           ▼
┌────────────────────┐
│ CIO                 │
│ IT戦略の統括        │
└──────────┬─────────┘
           │
           ▼
┌────────────────────┐
│ 情報システム部門     │
│ 企画・開発・運用     │
└──────────┬─────────┘
           │
           ▼
┌────────────────────┐
│ 各業務部門           │
│ ITの利用・改善提案  │
└────────────────────┘
```

これは組織体制の一例です。

実際の組織では、IT委員会やリスク管理部門、内部監査部門などが関与する場合もあります。

---

## 7-2. CIOとは

**CIO（Chief Information Officer：最高情報責任者）**とは、企業の情報戦略やIT戦略を統括する経営幹部です。

主な役割には、

- 情報システム戦略の立案
- IT投資の管理
- IT資源の最適化
- 情報システム部門の統括
- 経営戦略とIT戦略の整合

などがあります。

CIOは、ITを経営にどのように活用するかを考える重要な役職です。

---

## 7-3. CISOとは

**CISO（Chief Information Security Officer：最高情報セキュリティ責任者）**とは、企業の情報セキュリティを統括する責任者です。

主な役割には、

- 情報セキュリティ方針の策定
- セキュリティリスクの管理
- セキュリティ対策の推進
- インシデント対応体制の整備

などがあります。

CIOとCISOは役割が異なります。

| 役職 | 主な役割 |
|---|---|
| CIO | 情報・IT戦略の統括 |
| CISO | 情報セキュリティの統括 |

---

## 7-4. ITマネジメントとの違い

ITガバナンスとITマネジメントは、似ていますが役割が異なります。

### ITガバナンス

ITの活用方針や意思決定の仕組みを整備し、組織として適切に統治することです。

### ITマネジメント

定められた方針や目標に基づいて、ITに関する活動を計画・実行・管理することです。

| 項目 | ITガバナンス | ITマネジメント |
|---|---|---|
| 主な役割 | 評価・方向付け・監視 | 計画・実行・管理 |
| 主な視点 | 組織全体の統治 | IT活動の運営 |
| 主な担当 | 経営層などの統治主体 | IT部門・管理者など |
| 例 | IT投資方針の決定 | システム導入計画の実行 |

---

# 8. IT投資戦略とは

## 8-1. IT投資戦略の基本

**IT投資戦略（IT Investment Strategy）**とは、経営目標の達成に向けて、ITにどの程度の予算を投じ、どのような効果を得るかを計画することです。

例えば、企業が新しい販売管理システムを導入するとします。

導入費用が1,000万円かかる場合、その投資によってどれくらいの効果が得られるのかを考える必要があります。

IT投資の効果には、次のようなものがあります。

- 人件費の削減
- 売上の増加
- 業務時間の短縮
- 顧客満足度の向上
- セキュリティリスクの低減

これらの効果を評価し、投資の妥当性を判断します。

---

# 9. IT投資評価の代表的な手法

IT投資評価では、投資に対してどれくらいの利益や効果が得られるかを分析します。

代表的な手法には、次の3つがあります。

1. PBP：回収期間法
2. DPP：割引回収期間法
3. NPV：正味現在価値法

---

# 10. PBP：回収期間法

## 10-1. PBPとは

**PBP（Payback Period：回収期間）**とは、投資した金額を回収するまでに必要な期間です。

PBPを利用して投資を評価する方法を、**回収期間法**と呼びます。

例えば、システム導入に600万円かかり、毎年200万円の正味キャッシュフローが得られるとします。

```text
初期投資：600万円

1年目：200万円
2年目：200万円
3年目：200万円
```

この場合、3年間で投資額を回収できます。

---

## 10-2. PBPの計算式

毎年同額の正味キャッシュフローが得られる場合、次の式で求められます。

**PBP = 初期投資額 ÷ 年間正味キャッシュフロー**

例えば、

```text
初期投資額：600万円

年間正味キャッシュフロー：200万円
```

の場合、

```text
PBP
= 600 ÷ 200

= 3年
```

となります。

**回収期間は3年**です。

---

## 10-3. PBPのメリット・デメリット

### メリット

- 計算が簡単
- 投資回収までの期間が分かる
- 資金回収の早さを比較しやすい

### デメリット

- お金の時間的価値を考慮しない
- 回収後に得られる利益を十分に評価できない
- 長期的な収益性を判断しにくい

---

# 11. DPP：割引回収期間法

## 11-1. DPPとは

**DPP（Discounted Payback Period：割引回収期間）**とは、将来得られるキャッシュフローを現在価値に割り引いたうえで、初期投資を回収するまでの期間です。

PBPとの大きな違いは、**お金の時間的価値を考慮すること**です。

---

## 11-2. お金の時間的価値とは

例えば、今すぐ100万円を受け取る場合と、1年後に100万円を受け取る場合を考えてみましょう。

一般的に、今すぐ受け取った100万円は運用などに利用できるため、将来受け取る100万円とは価値が異なります。

そこで、将来のお金を現在の価値に換算します。

この考え方を、**現在価値（Present Value）**と呼びます。

---

## 11-3. 現在価値の計算式

将来のキャッシュフローの現在価値は、次の式で求められます。

**現在価値 = 将来のキャッシュフロー ÷（1 + 割引率）ⁿ**

- 割引率：r
- n：経過年数

例えば、1年後に受け取る110万円を、割引率10%で現在価値に換算すると、

```text
現在価値
= 110 ÷ 1.1

= 100万円
```

となります。

---

## 11-4. DPPの計算例

次のIT投資を考えてみましょう。

```text
初期投資：300万円

年間正味キャッシュフロー：120万円

割引率：10%
```

まず、各年のキャッシュフローを現在価値に換算します。

| 年 | キャッシュフロー | 現在価値 |
|---|---:|---:|
| 1年目 | 120万円 | 約109.09万円 |
| 2年目 | 120万円 | 約99.17万円 |
| 3年目 | 120万円 | 約90.16万円 |
| 4年目 | 120万円 | 約81.96万円 |

3年目までの累計現在価値は、

```text
109.09 + 99.17 + 90.16

= 298.42万円
```

です。

まだ初期投資の300万円を回収できていません。

4年目までの累計現在価値は、

```text
298.42 + 81.96

= 380.38万円
```

となります。

したがって、**割引回収期間は4年目**です。

なお、年末に一括してキャッシュフローを受け取る前提では、回収時点は4年目末です。年内に均等に発生すると近似する場合は、3年を少し超えた時点と見積もる方法もあります。

---

## 11-5. PBPとDPPの違い

| 比較項目 | PBP | DPP |
|---|---|---|
| 正式名称 | Payback Period | Discounted Payback Period |
| 日本語 | 回収期間 | 割引回収期間 |
| 時間的価値 | 考慮しない | 考慮する |
| 計算 | 比較的簡単 | 割引計算が必要 |
| 特徴 | 回収の早さを評価 | 現在価値を考慮して回収を評価 |

---

# 12. NPV：正味現在価値法

## 12-1. NPVとは

**NPV（Net Present Value：正味現在価値）**とは、将来得られるキャッシュフローの現在価値の合計から、初期投資額を差し引いた金額です。

NPVを利用して投資の妥当性を評価する方法を、**正味現在価値法**と呼びます。

---

## 12-2. NPVの計算式

**NPV = 将来キャッシュフローの現在価値の合計 − 初期投資額**

数式で表すと、

**NPV = Σ［CFₜ /（1 + r）ᵗ］− I₀**

です。

- CFₜ：t年目の正味キャッシュフロー
- r：割引率
- t：年数
- I₀：初期投資額

※この式は、初期投資を時点0で支払い、その後の正味キャッシュフローを各年末に受け取るモデルです。

---

## 12-3. NPVの計算例

次のIT投資を考えてみましょう。

```text
初期投資：300万円

1年目：120万円
2年目：120万円
3年目：120万円

割引率：10%
```

各年の現在価値を求めます。

### 1年目

```text
120 ÷ 1.1

≒ 109.09万円
```

### 2年目

```text
120 ÷ 1.1²

≒ 99.17万円
```

### 3年目

```text
120 ÷ 1.1³

≒ 90.16万円
```

現在価値の合計は、

```text
109.09 + 99.17 + 90.16

= 298.42万円
```

です。

したがって、

```text
NPV
= 298.42 − 300

= −1.58万円
```

となります。

**NPVは約−1.58万円**です。

---

## 12-4. NPVの判断基準

一般的には、次のように判断します。

| NPV | 判断 |
|---|---|
| NPV > 0 | 投資によって価値が増加すると評価できる |
| NPV = 0 | 割引率に相当する収益性が見込まれる |
| NPV < 0 | 設定した割引率では投資の価値が不足する |

ただし、実際の投資判断では、NPVだけでなく、リスクや戦略的重要性なども考慮します。

---

# 13. PBP・DPP・NPVの比較

| 手法 | 正式名称 | 評価するもの | 時間的価値 |
|---|---|---|---|
| PBP | Payback Period | 投資回収までの期間 | 考慮しない |
| DPP | Discounted Payback Period | 割引後の投資回収期間 | 考慮する |
| NPV | Net Present Value | 投資による価値の増減 | 考慮する |

### 🍯 覚え方

**PBPは「何年で回収できる？」**

**DPPは「お金の時間的価値を考えると何年で回収できる？」**

**NPVは「投資すると現在価値でいくら得する？」**

---

# 14. 業務プロセスの改善とは

企業では、業務の効率化や品質向上を目的として、業務プロセスの改善を行います。

例えば、

- 紙の申請書を電子化する
- 承認作業を自動化する
- 重複した作業をなくす
- 業務の一部を外部委託する

といった取り組みです。

業務改善には、さまざまな手法があります。

---

# 15. BPRとは

## 15-1. BPRの基本

**BPR（Business Process Reengineering）**とは、企業の業務プロセスを根本から見直し、再設計することです。

BPRの特徴は、既存の業務を少しずつ改善するのではなく、**業務の仕組みそのものを抜本的に見直すこと**です。

---

## 15-2. BPRの例

例えば、紙の申請書を利用する業務を考えてみましょう。

### 改善前

```text
申請書を印刷
      │
      ▼
手書きで記入
      │
      ▼
上司へ提出
      │
      ▼
承認印を押す
      │
      ▼
担当部署へ郵送
      │
      ▼
システムへ入力
```

この業務では、紙の印刷や郵送、手入力など、多くの作業が発生します。

### BPR実施後

```text
Webフォームで申請
        │
        ▼
自動チェック
        │
        ▼
電子承認
        │
        ▼
データを自動登録
```

このように、業務の流れを根本から見直すことがBPRです。

---

# 16. BPMとは

## 16-1. BPMの基本

**BPM（Business Process Management）**とは、業務プロセスを継続的に管理・分析・改善する考え方です。

BPRが抜本的な業務改革に重点を置くのに対し、BPMは継続的な改善に重点を置きます。

---

## 16-2. BPMの流れ

BPMでは、次のようなサイクルを繰り返します。

```text
業務プロセスの設計
        │
        ▼
業務の実行
        │
        ▼
業務の監視
        │
        ▼
問題点の分析
        │
        ▼
業務の改善
        │
        └──────→ 設計へ戻る
```

例えば、申請業務の平均処理時間を測定し、時間がかかっている工程を改善する場合などが該当します。

---

## 16-3. BPRとBPMの違い

| 比較項目 | BPR | BPM |
|---|---|---|
| 正式名称 | Business Process Reengineering | Business Process Management |
| 主な目的 | 業務の抜本的改革 | 業務の継続的改善 |
| 改善の規模 | 大きいことが多い | 継続的・段階的 |
| 主な特徴 | 業務の仕組みを再設計 | 業務を管理・分析・改善 |

---

# 17. IDEALモデルとは

## 17-1. IDEALの基本

**IDEALモデル**とは、組織のプロセス改善を進めるためのモデルです。

IDEALは、次の5つの段階の頭文字を組み合わせたものです。

1. Initiating
2. Diagnosing
3. Establishing
4. Acting
5. Learning

---

## 17-2. IDEALの5段階

### ① Initiating：開始

改善活動の目的や必要性を明確にします。

例えば、業務の処理時間を短縮するという目標を設定します。

### ② Diagnosing：診断

現在の業務や組織の状態を分析し、問題点を把握します。

例えば、申請処理に時間がかかっている原因を調査します。

### ③ Establishing：確立

改善方針や計画を策定します。

例えば、電子承認システムの導入計画を作成します。

### ④ Acting：実行

改善計画を実行します。

例えば、電子承認システムを導入し、業務手順を変更します。

### ⑤ Learning：学習

改善活動の結果を評価し、次の改善に活かします。

例えば、導入前後の処理時間を比較し、改善効果を確認します。

---

## 17-3. IDEALモデルの流れ

```text
Initiating
   開始
    │
    ▼
Diagnosing
   診断
    │
    ▼
Establishing
   確立
    │
    ▼
Acting
   実行
    │
    ▼
Learning
   学習
    │
    └──────→ 次の改善へ
```

---

# 18. BPOとは

## 18-1. BPOの基本

**BPO（Business Process Outsourcing）**とは、企業の業務プロセスの一部または全部を外部の専門企業などに委託することです。

例えば、

- 給与計算
- コールセンター業務
- データ入力
- 経理業務
- 人事関連業務

などを外部委託する場合があります。

---

## 18-2. BPOのメリット

### ① コスト削減

外部の専門企業に委託することで、業務コストを削減できる場合があります。

### ② 専門性の活用

専門知識を持つ企業のノウハウを活用できます。

### ③ コア業務への集中

自社の競争力に直結する業務へ、人材や予算を集中できます。

---

## 18-3. BPOのデメリット

- 外部委託先への依存
- 情報漏えいリスク
- 業務ノウハウの蓄積不足
- 委託先との調整コスト

BPOでは、委託する業務の範囲や責任分担を明確にすることが重要です。

---

# 19. RPAとは

## 19-1. RPAの基本

**RPA（Robotic Process Automation）**とは、ソフトウェアロボットを利用して、主に定型的な事務作業を自動化する技術です。

例えば、

- Excelからデータを読み取る
- システムへ情報を入力する
- 定型的なメールを送信する
- 複数システム間でデータを転記する

といった作業を自動化できます。

---

## 19-2. RPAの仕組み

```text
Excelファイル
      │
      ▼
┌──────────────┐
│ RPAロボット   │
│ データを取得  │
└──────┬───────┘
       │
       ▼
業務システムへ入力
       │
       ▼
処理結果を保存
```

RPAを導入することで、人間が繰り返し行っていた作業を自動化できます。

---

## 19-3. RPAのメリット

- 定型作業の効率化
- 入力ミスの削減
- 作業時間の短縮
- 人手不足への対応

---

## 19-4. RPAの注意点

RPAは、すべての業務を自動化できるわけではありません。

例えば、複雑な判断が必要な業務や、頻繁に手順が変更される業務には適さない場合があります。

また、画面操作を自動化するRPAでは、システムの画面構成が変更されると、ロボットが正常に動作しなくなる場合があります。

そのため、RPAを導入する前に、業務そのものを整理することが重要です。

---

# 20. ワークフローシステムとは

## 20-1. ワークフローシステムの基本

**ワークフローシステム（Workflow System）**とは、申請・承認などの業務手続きを電子化し、業務の流れを管理するシステムです。

例えば、経費精算の申請を考えてみましょう。

```text
従業員
  │
  ▼
経費申請
  │
  ▼
上司の承認
  │
  ▼
経理部門の確認
  │
  ▼
支払処理
```

この一連の業務をシステム上で管理します。

---

## 20-2. ワークフローシステムのメリット

### ① 業務の効率化

紙の申請書や押印を減らせます。

### ② 進捗状況の可視化

申請がどの段階にあるのかを確認できます。

### ③ 承認ルールの統一

決められた承認経路に沿って処理できます。

### ④ 履歴の管理

誰がいつ申請・承認したのかを記録できます。

---

# 21. 業務改善手法の比較

| 手法 | 正式名称 | 主な目的 |
|---|---|---|
| BPR | Business Process Reengineering | 業務の抜本的改革 |
| BPM | Business Process Management | 業務の継続的改善 |
| IDEAL | Initiating, Diagnosing, Establishing, Acting, Learning | プロセス改善の体系化 |
| BPO | Business Process Outsourcing | 業務の外部委託 |
| RPA | Robotic Process Automation | 定型作業の自動化 |
| ワークフローシステム | Workflow System | 申請・承認などの電子化 |

これらは、目的が異なるため、組み合わせて利用することもあります。

例えば、BPRによって業務を見直し、その一部をRPAで自動化することも可能です。

---

# 22. ソリューションサービスとは

## 22-1. ソリューションサービスの基本

**ソリューションサービス（Solution Service）**とは、顧客や企業が抱える課題を解決するために提供されるサービスです。

例えば、

- クラウドサービスの導入
- 業務システムの構築
- システム間連携の実現
- ITインフラの整備
- セキュリティ対策の導入

などが該当します。

重要なのは、単に製品を提供するのではなく、**顧客の課題を解決すること**です。

---

# 23. クラウドサービス

## 23-1. クラウドサービスとは

**クラウドサービス（Cloud Service）**とは、サーバやストレージ、ソフトウェアなどのIT資源を、ネットワーク経由で利用できるサービスです。

例えば、企業が新しいシステムを構築するとき、必ずしも自社で物理サーバを購入する必要はありません。

クラウドサービスを利用することで、必要なIT資源を柔軟に利用できます。

---

## 23-2. クラウドサービスの主な種類

代表的なサービスモデルには、次の3つがあります。

### SaaS

**SaaS（Software as a Service）**とは、ソフトウェアをサービスとして提供する形態です。

利用者は、提供されるアプリケーションを利用します。

### PaaS

**PaaS（Platform as a Service）**とは、アプリケーションを開発・実行するためのプラットフォームを提供する形態です。

### IaaS

**IaaS（Infrastructure as a Service）**とは、仮想サーバやストレージ、ネットワークなどのITインフラを提供する形態です。

---

## 23-3. SaaS・PaaS・IaaSの比較

| 項目 | SaaS | PaaS | IaaS |
|---|---|---|---|
| 主な提供対象 | アプリケーション | 開発・実行環境 | ITインフラ |
| 利用者の管理範囲 | 比較的小さい | 中程度 | 比較的大きい |
| 主な用途 | 業務ソフトの利用 | アプリ開発 | サーバ構築 |

---

# 24. SOAとは

## 24-1. SOAの基本

**SOA（Service-Oriented Architecture：サービス指向アーキテクチャ）**とは、システムの機能を独立したサービスとして整理し、それらを組み合わせてシステムを構築する考え方です。

例えば、ECサイトには次のような機能があります。

- 顧客管理
- 商品管理
- 在庫管理
- 決済処理
- 配送管理

SOAでは、これらの機能をサービスとして整理します。

---

## 24-2. SOAの構成例

```text
┌────────────────────┐
│ ECサイト            │
└──────────┬─────────┘
           │
           ▼
┌────────────────────┐
│ サービス連携        │
└──────────┬─────────┘
           │
  ┌────────┼────────┐
  │        │        │
  ▼        ▼        ▼
顧客管理  在庫管理  決済処理
サービス  サービス  サービス
```

各サービスは、定義されたインターフェースを通じて利用されます。

そのため、ほかのシステムから同じサービスを再利用することもできます。

---

## 24-3. SOAのメリット

### ① サービスの再利用

一度作成したサービスを、複数のシステムから利用できます。

### ② システム間連携の促進

異なるシステムの機能を組み合わせやすくなります。

### ③ 変更への対応

サービス間の依存関係を適切に管理することで、一部の機能を変更しやすくなります。

---

## 24-4. SOAの注意点

SOAでは、サービスの設計や管理が重要です。

サービス間の依存関係が複雑になると、変更や障害調査が難しくなる場合があります。

また、サービス間通信による性能面の負担も考慮する必要があります。

---

# 25. ESBとは

## 25-1. ESBの基本

**ESB（Enterprise Service Bus）**とは、異なるシステムやサービス間の連携を支援するための仕組みです。

システム間の通信を仲介し、メッセージの配送やデータ形式の変換などを行います。

---

## 25-2. ESBを利用しない場合

例えば、4つのシステムが相互に連携する場合を考えます。

```text
システムA ─── システムB
    │  ＼     ／  │
    │    ＼ ／    │
    │    ／ ＼    │
    │  ／     ＼  │
システムC ─── システムD
```

各システムが個別に連携すると、接続関係が複雑になる場合があります。

---

## 25-3. ESBを利用した場合

```text
システムA   システムB
    │          │
    └────┬─────┘
         │
         ▼
┌────────────────┐
│ ESB            │
│ メッセージ連携 │
│ データ変換     │
│ 経路制御       │
└────────┬───────┘
         │
    ┌────┴─────┐
    │          │
システムC   システムD
```

ESBを利用することで、システム間連携の共通機能をまとめられます。

---

## 25-4. ESBの主な機能

### ① メッセージルーティング

メッセージを適切なサービスへ配送します。

### ② データ変換

異なるシステム間で、データ形式を変換します。

### ③ プロトコル変換

異なる通信方式を利用するシステム間の連携を支援します。

### ④ サービス連携

複数のサービスを組み合わせて利用できるようにします。

---

# 26. SOAとESBの違い

SOAとESBは、関連していますが、同じものではありません。

### SOA

サービスを組み合わせてシステムを構築する**設計思想**です。

### ESB

サービスやシステム間の連携を支援する**技術的な仕組み**です。

| 比較項目 | SOA | ESB |
|---|---|---|
| 正式名称 | Service-Oriented Architecture | Enterprise Service Bus |
| 日本語 | サービス指向アーキテクチャ | エンタープライズサービスバス |
| 主な役割 | サービス中心の設計 | サービス間の連携 |
| 分類 | アーキテクチャの考え方 | 連携基盤・ミドルウェア |
| 関係 | ESBを利用する場合がある | SOAを支援できる |

なお、SOAを実現するためにESBが必須というわけではありません。

APIなどを利用してサービス間連携を実現する方法もあります。

# 28. 練習問題

最後に、応用情報技術者試験を意識した問題を解いてみましょう。

## 問題1：EA

EAにおいて、業務プロセスや組織の役割を整理する体系はどれでしょうか。

A. DA  
B. AA  
C. BA  
D. TA

### 解答

**正解：C. BA**

BAは、Business Architectureの略で、業務や組織の構造を整理する体系です。

---

## 問題2：ITガバナンス

ITガバナンスの説明として、最も適切なものはどれでしょうか。

A. IT機器の故障を修理すること  
B. ITの活用方針や意思決定を統治する仕組み  
C. プログラムの実行速度を測定すること  
D. データベースのテーブルを設計すること

### 解答

**正解：B**

ITガバナンスは、組織がITを適切に活用するための統治の仕組みです。

---

## 問題3：PBP

ある企業がシステム導入に800万円を投資しました。

毎年200万円の正味キャッシュフローが得られる場合、単純回収期間は何年でしょうか。

### 解答

```text
PBP
= 800 ÷ 200

= 4年
```

**答え：4年**

---

## 問題4：NPV

初期投資100万円、1年後の正味キャッシュフロー110万円、割引率10%の場合、NPVはいくらでしょうか。

### 解答

```text
現在価値
= 110 ÷ 1.1

= 100万円

NPV
= 100 − 100

= 0万円
```

**答え：0万円**

---

## 問題5：業務改善

既存の業務プロセスを根本から見直し、抜本的に再設計する手法はどれでしょうか。

A. BPM  
B. BPR  
C. BPO  
D. RPA

### 解答

**正解：B. BPR**

BPRは、Business Process Reengineeringの略です。

---

## 問題6：SOAとESB

SOAとESBの説明として、適切な組み合わせはどれでしょうか。

A. SOAは連携基盤、ESBは設計思想  
B. SOAは設計思想、ESBは連携基盤  
C. SOAもESBもデータベース管理方式  
D. SOAもESBもネットワークの冗長化方式

### 解答

**正解：B**

SOAはサービス指向の設計思想、ESBはサービス間連携を支援する仕組みです。
