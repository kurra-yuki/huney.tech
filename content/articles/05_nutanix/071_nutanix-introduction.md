# Nutanixとは？HCIから理解するNutanix入門【NCA 7.5対策】

## はじめに

企業のシステムでは、Webサーバーやデータベースサーバーなど、さまざまなサーバーが利用されています。

こうしたシステムを動かすためには、単純にサーバーを用意するだけではありません。

たとえば、

- サーバー
- ストレージ
- ネットワーク
- 仮想化基盤

など、さまざまなITインフラが必要になります。

従来は、これらをそれぞれ別々の機器として構築する方法が一般的でした。

しかし、システムが大規模になるほど構成が複雑になり、管理も難しくなっていきます。

そこで登場した考え方が、

**HCI（Hyper-Converged Infrastructure：ハイパーコンバージドインフラストラクチャ）**

です。

そして、このHCIを代表する製品・プラットフォームを提供している企業の一つが**Nutanix**です。

今回はNCA（Nutanix Certified Associate）を学習する第一歩として、

**「そもそもNutanixとは何なのか？」**

というところから学んでいきましょう。

---

# 従来のインフラ構成

まずはNutanixを理解するために、従来のインフラ構成について確認しましょう。

従来の仮想化環境では、

- サーバー
- ネットワーク
- ストレージ

をそれぞれ独立した機器として用意する構成が一般的です。

このような構成は、一般的に**3Tier（3層）構成**と呼ばれます。

イメージすると、

```text
┌──────────────┐
│    Server    │
│    Server    │
│    Server    │
└──────┬───────┘
       │
┌──────▼───────┐
│   Network    │
│   Switch     │
└──────┬───────┘
       │
┌──────▼───────┐
│   Storage    │
│  SAN / NAS   │
└──────────────┘
```

という構成です。

サーバーで処理を行い、データは外部ストレージへ保存します。

その間をネットワークが接続しています。

この構成には、それぞれの機器を個別に選択・拡張できるメリットがあります。

一方で、

**「サーバーはサーバー、ストレージはストレージとして別々に管理する必要がある」**

という特徴があります。

そのため、環境が大きくなるほど構築や管理が複雑になりやすくなります。

---

# HCIとは？

そこで登場するのが**HCI**です。

HCIは、

**Hyper-Converged Infrastructure**

の略です。

日本語では「ハイパーコンバージドインフラストラクチャ」と呼ばれます。

HCIでは、

- コンピュート
- ストレージ
- 仮想化

などの機能を、汎用的なサーバーを中心としたソフトウェア定義の基盤として統合します。

従来の3Tier構成では外部ストレージを用意することが一般的でした。

一方HCIでは、各サーバーが持っているローカルストレージをソフトウェアによってまとめて利用します。

イメージとしては、

```text
従来

Server ─ Network ─ Storage


HCI

┌──────────────────┐
│       Node       │
│ Compute + Storage│
├──────────────────┤
│       Node       │
│ Compute + Storage│
├──────────────────┤
│       Node       │
│ Compute + Storage│
└──────────────────┘
        ↓
 ソフトウェアで統合管理
```

となります。

HCIでは複数のノードをまとめて**クラスタ**として利用します。

これによって、従来のようにサーバーとストレージを別々の大きなシステムとして管理するのではなく、統合されたインフラとして扱いやすくなります。

---

# Nutanixとは？

Nutanixは、この**HCIを中心としたクラウドプラットフォームを提供している企業**です。

Nutanixの特徴は、単に「サーバーとストレージを一体化した製品」というだけではありません。

コンピュート、ストレージ、仮想化、ネットワークなどのインフラ機能をソフトウェアによって統合し、管理しやすいプラットフォームとして提供しています。

つまり、

> **複雑になりがちなITインフラを、できるだけシンプルに構築・管理できるようにする**

というのがNutanixを理解するうえで重要なポイントです。

---

# Nutanix Cloud Infrastructure（NCI）

NCAを勉強すると、頻繁に登場するのが

**NCI（Nutanix Cloud Infrastructure）**

です。

NCIは、Nutanixが提供するクラウドインフラストラクチャ基盤です。

NCIでは、

- コンピュート
- ストレージ
- 仮想化
- ネットワーク
- セキュリティ

など、仮想化環境を構築・運用するためのさまざまな機能を提供します。

NutanixはもともとHCIで知られるようになりましたが、現在は単なるHCI製品だけではなく、オンプレミスやクラウドを含めたインフラ環境を統合的に扱うプラットフォームへと発展しています。

その中心となる基盤の一つがNCIです。

NCAでは、

**「NCIによって何ができるのか」**

という考え方が重要になります。

---

# Nutanixの基本構成

Nutanixでは、複数の**Node（ノード）**をまとめて利用します。

ノードとは、簡単にいえばNutanix環境を構成するサーバーです。

```text
        Nutanix Cluster

┌─────────┐
│ Node 1  │
├─────────┤
│ Node 2  │
├─────────┤
│ Node 3  │
└─────────┘
```

複数のノードをまとめたものを**Cluster（クラスタ）**と呼びます。

そして各ノードが持っているCPU、メモリ、ストレージなどのリソースを利用して、仮想マシンなどのワークロードを動作させます。

そのため、

**Node → Cluster → VM**

という関係を最初にイメージしておくと、今後のNutanix学習がかなり分かりやすくなります。

---

# Nutanixと仮想化

Nutanixでは仮想マシンを動かすために**ハイパーバイザー**を利用します。

Nutanixが提供しているハイパーバイザーが、

**AHV（Acropolis Hypervisor）**

です。

AHVを利用することで、Nutanix環境上に仮想マシンを作成して動作させることができます。

```text
┌───────────────────┐
│        VM         │
│        VM         │
│        VM         │
├───────────────────┤
│        AHV        │
├───────────────────┤
│ Nutanix Platform  │
├───────────────────┤
│    Hardware       │
└───────────────────┘
```

NCAではAHVも重要な用語なので、

**「Nutanixが提供するハイパーバイザー」**

というところから覚えておきましょう。

AHVについては別の記事で詳しく解説します。

---

# Nutanixを管理するPrism

Nutanix環境を管理するときに利用する重要なツールが、

**Prism**

です。

Prismは、Nutanix環境をWebブラウザから管理するための管理インターフェースです。

Prismを利用すると、

- 仮想マシンの管理
- ストレージの管理
- ネットワークの管理
- クラスタの状態確認
- アラートの確認
- パフォーマンス監視

などを行うことができます。

つまり、

> **Nutanix環境を管理するためのコントロールパネル**

のような存在です。

NCAではPrismを使った基本操作や、画面から必要な情報を読み取る知識も重要になります。

Prismについても、今後の記事で詳しく扱います。

---

# Nutanixを使うメリット

Nutanixを利用する大きな目的の一つが、**インフラ管理のシンプル化**です。

従来の3Tier構成では、

```text
サーバー管理
     +
ネットワーク管理
     +
ストレージ管理
     +
仮想化環境管理
```

のように、それぞれを意識して管理する必要があります。

Nutanixでは、これらのインフラ機能をソフトウェアによって統合し、Prismなどを利用して管理できます。

また、システムを拡張するときには、必要に応じてノードを追加してクラスタのリソースを増やしていくという考え方を取ることができます。

これを**Scale-Out（スケールアウト）**と呼びます。

```text
3 Nodes

[Node][Node][Node]

       ↓

リソースが必要になった

       ↓

[Node][Node][Node][Node]
                  ↑
                追加
```

このように、必要に応じてノードを追加していける点もHCIの大きな特徴です。

# はちみつ屋さんで例えると？

従来の3Tier構成を、はちみつ屋さんで考えてみましょう。

従来のお店では、

- はちみつを作る工場
- 商品を保管する倉庫
- 商品を運ぶ配送センター

が、それぞれ別々の場所にあるとします。

それぞれ専門的に管理できますが、お店が大きくなってくると、

「工場の管理」

「倉庫の管理」

「配送センターの管理」

をそれぞれ考えなければなりません。

これが従来の3Tier構成に近いイメージです。

一方、HCIでは、

**「製造・保管などに必要な設備をまとめた店舗を複数並べて運営する」**

ようなイメージになります。

お客さんが増えて処理能力が足りなくなったら、

**新しい店舗（Node）を追加する。**

そして複数の店舗をまとめたものが、

**Cluster**

です。

さらにNutanixでは、それらの店舗をまとめて確認・管理するための管理室として、

**Prism**

があります。

このイメージを持っておくと、

- Node
- Cluster
- Prism
- Scale-Out

の関係が理解しやすくなります。

---

# NCA対策として覚えておきたいポイント

今回の内容で、まず押さえておきたいのは次のポイントです。

| 用語 | 意味 |
|---|---|
| Nutanix | HCIを中心としたクラウドプラットフォームを提供する企業 |
| HCI | コンピュートやストレージなどをソフトウェアによって統合したインフラ |
| NCI | Nutanix Cloud Infrastructure |
| Node | Nutanixクラスタを構成するサーバー |
| Cluster | 複数のノードをまとめた構成 |
| AHV | Nutanixが提供するハイパーバイザー |
| Prism | Nutanix環境を管理するための管理インターフェース |
| Scale-Out | ノードなどを追加してシステム全体の処理能力を拡張する考え方 |

特に、

```text
従来の3Tier
      ↓
HCI
      ↓
Nutanix
      ↓
NodeをClusterとして構成
      ↓
AHV上でVMを実行
      ↓
Prismから管理
```

という大きな流れを理解しておきましょう。

# まとめ

今回はNCA学習の第一歩として、NutanixとHCIについて学びました。

従来のインフラでは、サーバー・ネットワーク・ストレージなどを個別に構築・管理する3Tier構成が一般的でした。

HCIでは、コンピュートやストレージなどの機能をソフトウェアによって統合し、よりシンプルなインフラ管理を目指します。

Nutanixは、このHCIを中心として発展してきたクラウドプラットフォームです。

まずは、

**「Nutanix＝HCIを中心に、インフラをソフトウェアで統合・管理するためのプラットフォーム」**

というイメージを持っておきましょう。

次回以降は、Nutanixを構成している技術について、さらに詳しく見ていきます。
