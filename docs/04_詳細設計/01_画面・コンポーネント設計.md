# 1. 本書の目的

本書はHuney Webサイトにおける各画面の構成、表示項目、コンポーネント構成、表示条件を定義する。

本書では主に以下を扱う。

- 共通レイアウト
- 各画面構成
- UIコンポーネント
- 表示条件
- レスポンシブ方針
- Optional項目の扱い
- 画面単位のエラー表示

データ型、frontmatter、取得処理等については別の詳細設計書で定義する。

---

```text

├─────────────────────────────┤

│ Main                        │
│                             │
├─────────────────────────────┤
│ Footer                      │
└─────────────────────────────┘
```

基本コンポーネント：

- `Header`
- `Footer`
- `MainContainer`

# 51. Optional項目の表示ルール

Huneyでは任意データが多いため、存在しない項目について空欄や壊れたUIを表示しない。

対象例：

- thumbnail
- updatedAt
- tags
- youtube
- relatedArticles
- relatedTerms
- ogImage

例：

```text
thumbnail = undefined
→ サムネイル領域を表示しない

youtube = undefined
→ YouTubeCalloutを表示しない

relatedArticles = []
→ RelatedArticlesを表示しない
```

# 52. 画像エラー時の方針

記事本文以外のサムネイル等で画像取得に失敗した場合でも、記事タイトル等の主要情報を閲覧可能にする。

画像がHuneyの利用を阻害しない設計とする。

# 53. レスポンシブ基本方針

## Smartphone

- 1カラムを基本
- ナビゲーションを簡略化
- ArticleCardは原則1列
- 本文幅を画面に合わせる
- 表・コードは必要に応じて横スクロール

## Tablet

- 1〜2カラム
- コンテンツ量に応じて調整

## Desktop

- 記事カード複数列
- 本文は最大幅を制限
- 左右の余白を十分確保

---

# 54. ブレークポイント

具体的な値はTailwind CSS等の標準ブレークポイントを基本とする。

独自ブレークポイントを大量に追加しない。

---

# 55. アニメーション方針

必要最低限とする。

許容例：

- ボタンhover
- カードhover
- モバイルメニュー開閉

不要なスクロールアニメーションや派手な演出は避ける。

---

# 56. アクセシビリティ方針

コンポーネント実装時に以下を考慮する。

- semantic HTML
- `aria-label`
- alt
- キーボード操作
- Focus状態
- 十分なコントラスト
- heading階層

---

# 57. 外部リンク

YouTube・GitHub・SNS等の外部リンクは、内部リンクと区別可能にすることが望ましい。

セキュリティ上必要な属性も実装時に考慮する。

---

# 58. ローディング表示

MVPでは静的コンテンツ中心のため、大規模なローディングUIを必要としない。

将来外部API等を導入した場合に別途設計する。

---

# 59. デザインの判断基準

画面・コンポーネントの実装で迷った場合は以下を優先する。

1. 初心者に理解しやすい
2. テキストが読みやすい
3. 目的のページへ移動しやすい
4. モバイルでも使いやすい
5. Huneyらしい
6. 実装を不必要に複雑にしない
