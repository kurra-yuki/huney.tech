# 2. SEO基本方針

Huneyでは検索エンジン向けの最適化よりも、まず利用者にとって分かりやすいコンテンツを優先する。

SEOは、

**「初心者向けの記事を必要としている人へ正しく届けるための仕組み」**

として利用する。

以下のような過度なSEOは行わない。

- 不自然なキーワード詰め込み
- 同じ内容の記事大量生成
- 検索順位だけを目的とした記事
- 内容と関係のないタイトル
- 誤解を招く見出し
- AI生成記事の無確認大量公開

---

# 3. URL基本方針

URLは短く意味のある構造とする。

記事：

```text
https://huney.uk/articles/{slug}
```

用語辞典：

```text
https://huney.uk/glossary/{slug}
```

その他：

```text
https://huney.uk/articles
https://huney.uk/glossary
https://huney.uk/videos
https://huney.uk/profile
https://huney.uk/search
```

---

# 4. URL変更方針

公開済みURLは原則として変更しない。

理由：

- 外部リンク維持
- 検索エンジン評価維持
- ブックマーク維持
- SNS共有URL維持

slug変更が必要になった場合はリダイレクトを検討する。

MVPでは高度なリダイレクト管理機能を必須としない。

---

# 5. title基本設計

すべてのページに適切なtitleを設定する。

トップページ例：

```text
Huney | はちみつと学ぶIT
```

記事例：

```text
VLANとは？初心者向けにやさしく解説 | Huney
```

用語例：

```text
VLANとは？ | IT用語辞典 | Huney
```

一覧ページ例：

```text
記事一覧 | Huney
```

---

# 6. title長さ

titleは内容を理解できる長さにする。

検索エンジン表示だけを意識して不自然に短くしたり長くしたりしない。

重要なキーワードは可能な限り前半に置く。

---

# 7. seoTitle

記事frontmatterに`seoTitle`が存在する場合はSEO用titleとして優先利用できる。

例：

```yaml
seoTitle: "VLANとは？仕組みとメリットを初心者向けに解説"
```

未設定の場合は記事タイトルから生成する。

優先順位：

```text
seoTitle
↓
title
```

---

# 8. description基本設計

各ページにdescriptionを設定する。

記事ではfrontmatterの`description`を基本利用する。

例：

```text
VLANとは何か、仕組みやメリットをIT初心者向けにやさしく解説します。
```

内容と一致しない説明文を設定しない。

---

# 9. canonical

すべての公開ページにcanonical URLを設定する。

記事例：

```text
https://huney.uk/articles/vlan
```

重複URLが存在する場合でも、正規URLをcanonicalとして指定する。

---

# 10. metadata生成

Next.jsのmetadata機能等を使用してページ単位でメタデータを生成する。

概念：

```ts
generateMetadata()
```

記事ページでは記事データから生成する。

入力：

- title
- seoTitle
- description
- slug
- publishedAt
- updatedAt
- thumbnail
- ogImage

生成対象：

- title
- description
- canonical
- Open Graph
- SNS用情報

# 12. 用語metadata生成

用語詳細では以下から生成する。

- term
- summary
- slug
- officialName

例：

```text
VLANとは？ | IT用語辞典 | Huney
```

---

# 13. Open Graph基本設計

SNS等でURLが共有された場合に適切な情報を表示できること。

設定対象：

- title
- description
- URL
- siteName
- image
- type

---

# 14. OGP画像優先順位

記事OGP画像は以下の優先順位とする。

```text
1. ogImage
2. thumbnail
3. Huney共通OGP
```

これにより、本文画像やサムネイルが存在しない記事でもOGPを表示できる。

---

# 15. 共通OGP

画像なし記事のためにHuney共通OGP画像を用意する。

想定配置：

```text
/public/images/brand/og-default.webp
```

内容：

- Huneyロゴ
- ブランド名
- 「はちみつと学ぶIT」
- ブランドカラー

情報量を増やしすぎない。

---

# 16. 記事専用OGP

必要に応じて記事ごとのOGP画像を利用できる。

例：

```yaml
ogImage: "/images/articles/vlan/og.webp"
```

記事公開の必須要件とはしない。

---

# 17. SNSカード

Open Graphと合わせて主要SNSで記事情報が適切に表示される構成を目指す。

具体的なサービス固有設定は実装時点の仕様に従う。

---

# 18. 構造化データ基本方針

検索エンジンへコンテンツ内容を正しく伝えるため、必要に応じてJSON-LDによる構造化データを利用する。

初期対象：

- Article
- BreadcrumbList
- WebSite

---

# 19. Article構造化データ

記事詳細ページではArticle系構造化データを設定する。

主な項目：

- headline
- description
- datePublished
- dateModified
- author
- image
- mainEntityOfPage

画像が存在しない場合に不正なimage URLを出力しない。

---

# 20. dateModified

`updatedAt`が存在する場合は利用する。

存在しない場合：

```text
dateModified = publishedAt
```

として扱ってもよい。

---

# 21. Breadcrumb構造化データ

記事詳細・用語詳細等でBreadcrumbListを設定する。

記事例：

```text
TOP
↓
記事
↓
VLANとは？
```

画面表示用Breadcrumbと整合すること。

---

# 22. WebSite構造化データ

トップページ等でHuney自体の基本情報を表現するために利用可能とする。

情報例：

- name
- url
- description

---

# 23. sitemap基本設計

検索エンジンへ公開ページを通知するため`/sitemap.xml`を生成する。

対象：

- トップページ
- 記事一覧
- 公開記事
- 用語辞典一覧
- 公開用語
- 動画一覧
- プロフィール

---

# 24. sitemap除外対象

以下は含めない。

- draft記事
- draft用語
- 404
- 内部確認用ページ
- Preview専用URL
- 検索結果ページ

`/search`は原則としてsitemapへ含めない。

---

# 25. sitemap記事情報

可能であれば記事ごとに以下を反映する。

- URL
- lastModified

`updatedAt`がある場合は優先する。

---

# 26. robots.txt

`/robots.txt`を提供する。

基本的に公開コンテンツはクロール可能とする。

例：

```text
User-agent: *
Allow: /

Sitemap: https://huney.uk/sitemap.xml
```

実際の記述はフレームワーク仕様に合わせる。

---

# 27. Preview環境

Preview環境は検索エンジンへインデックスされないことが望ましい。

Vercel等のPreview URLについてはnoindex等を利用するか、ホスティング側の設定を利用する。

---

# 28. 下書きコンテンツ

draftコンテンツは本番環境でページ生成・公開しない。

そのため原則として検索エンジンからアクセス不能とする。

---

# 29. noindex

必要なページのみnoindexを利用する。

対象候補：

- 検索結果
- Preview
- 将来作成する管理用ページ

公開記事や用語詳細へ誤ってnoindexを付与しない。

---

# 30. 見出し構造

各ページの見出し構造を適切にする。

記事詳細では原則：

```text
h1 → 記事タイトル

h2 → 大見出し

h3 → h2配下の小見出し
```

見た目のためだけに見出しレベルを飛ばさない。

---

# 31. 記事タイトル

1ページにつき主要な`h1`は原則1つとする。

記事タイトルを`h1`とする。

---

# 32. 内部リンク

記事本文、関連記事、用語辞典等から関連するHuney内ページへリンクする。

目的：

- 初心者が関連内容を学びやすくする
- ページ間の関係を検索エンジンへ伝える

SEO目的だけで無意味な内部リンクを大量設置しない。

---

# 33. アンカーテキスト

リンク先が理解できる文言を使用する。

推奨：

```text
VLANについて詳しく見る
```

避ける例：

```text
こちら
```

ただし文章として不自然になる場合は無理に長くしない。

---

# 34. 外部リンク

公式情報等への外部リンクを適切に使用する。

特に技術記事では可能な範囲で一次情報へのリンクを活用する。

例：

- ベンダー公式ドキュメント
- RFC
- 製品公式ページ

---

# 35. 外部リンクのSEO属性

すべての外部リンクへ一律でnofollowを設定しない。

広告・スポンサー等が将来発生する場合は、その用途に応じた属性を設定する。

---

# 36. 画像SEO

画像を利用する場合は適切なaltを設定する。

例：

```text
VLANで部署ごとにネットワークを分割した構成図
```

画像の内容と関係のないキーワードをaltへ詰め込まない。

---

# 37. ファイル名

画像名は意味のある名称を推奨する。

例：

```text
vlan-network-flow.webp
```

以下は避ける。

```text
image001.webp
```

---

# 38. パフォーマンスとSEO

ページ表示速度はユーザー体験とSEO双方に影響するため以下を意識する。

- 画像最適化
- 不要なJavaScript削減
- 外部スクリプト削減
- フォント最適化
- レイアウトシフト抑制

ただし具体的な数値目標はMVPでは設定しない。

---

# 39. 404基本方針

存在しないURLへのアクセスでは404ページを表示する。

対象例：

```text
/articles/not-exists
/glossary/not-exists
```

---

# 40. 404表示内容

404画面には以下を表示する。

- ページが見つからないこと
- 簡単な説明
- トップへのリンク
- 記事一覧へのリンク

例：

```text
ページが見つかりませんでした。

お探しのページは、
移動または削除された可能性があります。

[トップへ戻る]
[記事を見る]
```

---

# 41. 404デザイン

Huneyらしい親しみやすさを持たせてもよい。

キャラクター利用可。

ただしエラー内容自体が分からなくならないようにする。

---

# 42. 記事404判定

以下の場合に404とする。

- slugに対応する記事が存在しない
- draft記事へ本番アクセス
- データ取得不能
- 必須データ不正により公開できない

---

# 43. 用語404判定

以下の場合に404とする。

- slug不存在
- draft
- データ取得不能

---

# 44. エラー種別

MVPでは概念上以下に分類する。

```text
404
→ コンテンツ不存在

500相当
→ アプリケーションまたは予期しない処理エラー
```

ユーザーへ技術的な例外内容を直接表示しない。

---

# 45. 500相当エラー

予期しないエラー時には、可能であれば共通エラー画面を表示する。

表示例：

```text
ページを表示できませんでした。

少し時間をおいてから、
もう一度お試しください。

[トップへ戻る]
```

---

# 46. エラー画面の情報量

ユーザーへ以下を表示しない。

- Stack Trace
- 内部ファイルパス
- 環境変数
- APIキー
- サーバー内部情報
- GitHub情報

---

# 47. 開発時エラー

ローカル開発環境では、原因調査のため十分な情報を確認できること。

例：

```text
Missing required frontmatter field: description
```

本番ユーザー向け画面とは分離する。

---

# 48. データ不正時

必須frontmatter不足等は可能な限りビルド時に検出する。

壊れた記事を本番公開するより、デプロイを失敗させる方を優先してよい。

---

# 49. 参照先不存在

関連記事や関連用語の参照先が存在しない場合は、ページ全体を500にしない。

該当リンクを除外し、可能であれば開発時に警告を出す。

---

# 50. 画像エラー

記事サムネイル等の画像が表示できない場合でも、記事タイトル・本文は表示可能にする。

画像は補助情報として扱う。

---

# 51. YouTubeリンクエラー

YouTubeリンクが設定されていても、リンク先の動画が削除される可能性がある。

MVPではYouTube APIによるリアルタイム存在確認を行わない。

運用時にリンク切れを確認する。

---

# 52. 検索エラー

検索結果0件はエラーではない。

Empty Stateとして正常表示する。

例：

```text
「VLAN123」に一致するコンテンツはありませんでした。
```

---

# 53. ログ基本方針

MVPでは専用ログ基盤を必須としない。

開発時：

- console
- Vercel等の実行ログ

を利用可能とする。

---

# 54. ログへ出さない情報

将来秘密情報を利用する場合、以下をログへ出さない。

- APIキー
- アクセストークン
- パスワード
- Cookie
- 個人情報

---

# 55. エラー監視

MVP公開後、必要性が出た段階でエラー監視サービス導入を検討する。

初期リリース必須ではない。

---

# 56. metadataエラー

記事固有の任意SEO情報がない場合は共通値へフォールバックする。

例：

```text
ogImageなし
↓
thumbnail
↓
Huney共通OGP
```

任意SEOデータ不足によってページ表示を失敗させない。

---

# 57. titleフォールバック

記事：

```text
seoTitle
↓
title
↓
エラー
```

`title`自体は必須データのため、存在しない記事はデータ不正として扱う。

---

# 58. descriptionフォールバック

記事descriptionは必須とする。

一覧ページ等の固定ページについてはサイト共通説明を設定可能とする。

---

# 59. サイト共通metadata

共通設定候補：

```text
siteName: Huney
domain: https://huney.uk
defaultTitle: Huney | はちみつと学ぶIT
```

デザイン・文言変更に対応しやすいよう共通管理する。

---

# 60. SEO設定配置

SEO関連共通設定は以下のような配置を想定する。

```text
config/
└── site.ts
```

例：

```ts
export const siteConfig = {
  name: "Huney",
  title: "Huney | はちみつと学ぶIT",
  url: "https://huney.uk"
}
```

---

# 61. metadata共通処理

必要に応じて共通関数を用意する。

概念：

```ts
buildMetadata()
```

目的：

- title形式統一
- canonical生成
- OGP共通値
- 共通画像フォールバック

---

# 62. sitemap生成処理

公開記事・公開用語等から自動生成する。

手作業で記事URLを追加する運用にはしない。

---

# 63. robots生成処理

フレームワークの標準機能を利用可能とする。

サイトURL等は共通設定から取得する。

---

# 64. 記事公開時のSEO処理

記事追加後：

```text
MDX追加
↓
Git Push
↓
Build
↓
記事ページ生成
↓
metadata生成
↓
sitemapへ追加
↓
Production公開
```

SEO専用の手作業をできるだけ必要としない。

---

# 65. 記事更新時のSEO処理

記事更新時：

```text
本文更新
↓
必要に応じてupdatedAt更新
↓
再Build
↓
metadata更新
↓
sitemap lastModified更新
```

---

# 66. 記事削除時

公開済み記事の削除は原則として慎重に行う。

削除する場合は、

- 本当に不要か
- 別記事へ統合できないか
- リダイレクトが必要か

を検討する。

MVPでは管理画面による削除機能は持たない。

---

# 67. SEO対象外ページ

検索結果ページ等、検索エンジンに価値が低いページはインデックス対象外を検討する。

例：

```text
/search
```

---

# 68. 重複コンテンツ

同じ記事を複数URLで公開しない。

外部プラットフォームへ同一記事を転載する場合は、Huneyをコンテンツの中心として扱う方針を検討する。

具体的な転載SEO運用は運用設計で定義可能とする。

---

# 69. Qiita等との関係

外部サービスへ記事を投稿する場合でも、Huneyを本拠地として運用する。

完全転載を行う場合は検索エンジン上の重複等を考慮する。

MVP公開後に運用ルールとして整理する。

---

# 70. SEO品質基準

記事公開前に最低限以下を確認する。

- titleが内容と一致
- descriptionが設定されている
- h1が適切
- 見出し構造が不自然でない
- slugが適切
- 内部リンクが壊れていない
- 画像利用時はaltがある
- 下書きではないことを確認

---

# 71. エラー品質基準

以下を満たすこと。

- 存在しないページで404になる
- 404から主要ページへ戻れる
- draftが本番公開されない
- 関連記事不存在でページが壊れない
- thumbnailなしでページが壊れない
- YouTubeなしでページが壊れない
- 予期しないエラーで秘密情報を表示しない

---
