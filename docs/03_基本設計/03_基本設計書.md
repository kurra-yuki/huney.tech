# 1. 本書の目的

本書は、要件定義書で定義したHuney Webサイトの要件について、どのようなシステム構成・画面構成・データ構成で実現するかを定義する。

本工程では主に以下を決定する。

- システム全体構成

- URL設計

コンポーネント単位の実装方法や具体的な処理ロジックについては詳細設計で定義する。

# 2. システム概要

Huneyは、IT初心者向けの記事・用語辞典・動画情報を提供する公開型Webサイトとする。

初期リリースではユーザー登録やログイン機能を持たない。

利用者はWebブラウザからアクセスし、以下のコンテンツを閲覧する。

- IT技術記事
- IT用語辞典
- 動画一覧
- プロフィール
- カテゴリ別コンテンツ
- 検索結果

Huneyでは、

```text
記事
→ 読んで理解する

用語辞典
→ 調べて理解する

YouTube
→ 見て理解する
```

という役割分担を基本とする。

# 4. 技術構成方針

初期システムでは以下を基本構成とする。

- フロントエンド：Next.js
- 言語：TypeScript
- スタイリング：Tailwind CSS

- コンテンツ管理：MarkdownまたはMDX

初期リリースではDBを利用しない。

---

# 5. DB利用方針

MVPでは以下の理由からDBを導入しない。

- ユーザー登録がない
- ログインがない
- ユーザーごとの情報を保持しない
- 記事・用語・動画情報をファイル管理できる
- 運用をできるだけ単純化したい

以下のような機能を追加する場合にDB導入を再検討する。

- ユーザー登録
- お気に入り
- 学習履歴
- 問題集
- コメント
- 会員機能
- 決済
- AI機能

---

# 6. コンテンツ管理方針

HuneyではコンテンツをGitHub上のファイルとして管理する。

想定構成：

```text
content/
├── articles/
├── glossary/
└── videos/
```

コンテンツ追加時にアプリ本体のコード修正を極力必要としない構成とする。

---

# 7. 記事管理方式

記事はMarkdownまたはMDXで管理する。

想定構成：

```text
content/
└── articles/
    ├── vlan.mdx
    ├── dns.mdx
    └── amazon-s3.mdx
```

記事はテキストのみでも公開できることを基本とする。

画像や動画がない場合でも正常に表示されること。

---

# 8. 記事メタデータ

各記事は本文とは別に以下の情報を保持する。

例：

```yaml
title: VLANとは？初心者向けにやさしく解説
slug: vlan
description: VLANの仕組みを初心者向けに解説します。
publishedAt: 2026-08-19
updatedAt: 2026-08-19
category: network
tags:
  - VLAN
  - ネットワーク
draft: false
```

必要に応じて以下を保持する。

```yaml
thumbnail:
youtube:
relatedArticles:
ogImage:
seoTitle:
```

`thumbnail` および `youtube` は任意項目とする。

---

# 9. 用語辞典管理

用語辞典もMarkdownまたはMDXで管理する。

```text
content/
└── glossary/
    ├── vlan.mdx
    ├── dns.mdx
    ├── nat.mdx
    └── vpn.mdx
```

- 読み方

- slug
- 一言説明

- 関連記事
- 関連用語

---

# 10. 動画管理

動画ファイルそのものはHuneyで保持しない。

YouTube等の外部動画サービスを利用する。

Huneyでは以下の情報のみ管理する。

- 動画タイトル
- URL
- カテゴリ
- 説明
- 公開日
- 必要に応じてサムネイル
- 関連記事

動画データはMVPでは静的ファイルとして管理する。

---

# 11. 画像管理方針

記事制作において画像を必須としない。

画像を利用する場合のみ以下のように管理する。

```text
public/
└── images/
    ├── brand/
    ├── mascot/
    ├── articles/
    ├── glossary/
    └── videos/
```

画像が存在しないコンテンツでも表示上問題が発生しないこと。

画像数や容量が増えた場合は、将来的に外部ストレージへの移行を検討する。

# 23. テキスト記事の設計方針

Huneyの記事では、画像がなくても内容を理解できる文章構成を重視する。

基本的な流れ：

```text
結論
↓
概要
↓
初心者向け説明
↓
具体例
↓
詳しい説明
↓
ポイント
↓
まとめ
```

すべての記事で同一構成を強制しない。

# 26. YouTube連携方針

YouTubeは記事の代替ではなく補完コンテンツとする。

**読むことで理解する**

**図・映像・音声で理解する**

記事から動画への移動を強制しない。

# 54. 設計上の重要方針

Huneyでは以下を優先する。

## 1. 初心者の理解

高度なUIより、理解しやすさを優先する。

## 2. テキスト記事の完成度

画像に頼りすぎず、文章だけでも基本的に理解できるようにする。

## 3. YouTubeとの役割分担

視覚的な理解が適している内容は動画を活用する。

## 4. 運用の簡単さ

記事公開までの工程を増やしすぎない。

## 5. MVPを肥大化させない

必要になるか分からない機能を先に実装しない。

## 6. 将来変更可能な構成

DB・CMS・画像ストレージ等を必要になった段階で導入できる構成とする。
