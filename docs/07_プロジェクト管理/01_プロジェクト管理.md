# 1. 目的

本ファイルは、Huney Webサイト構築プロジェクトの進捗を管理するためのプロジェクト管理表である。

人間だけでなく、GitHub Copilot等のAIエージェントからも参照・更新することを前提とする。

プロジェクトの実装・修正・テストを行った場合は、必要に応じて本ファイルのタスク状態も更新する。

---

# 2. 管理方針

プロジェクトでは以下を基本とする。

- 1つの作業を1タスクとして管理する
- 各タスクには一意のTask IDを付与する
- 完了したタスクは削除しない
- ステータスと進捗率を実際の状態に合わせる
- 新しい作業が必要になった場合はタスクを追加する
- 問題が発生した場合は課題管理表へ登録する
- 設計変更が必要な場合は該当設計書も更新する
- Gitの履歴から管理表の変更履歴を確認できる状態にする

---

# 3. ステータス

使用可能なステータスは以下とする。

| ステータス | 意味 |
|---|---|
| 未着手 | まだ作業を開始していない |
| 進行中 | 現在作業している |
| レビュー待ち | 実装等が完了し確認待ち |
| 保留 | 何らかの理由で作業を停止している |
| 完了 | 作業および必要な確認が完了している |

独自のステータスは原則追加しない。

---

# 4. 優先度

| 優先度 | 意味 |
|---|---|
| 高 | MVP公開または他タスクに大きく影響する |
| 中 | 必要だが即時対応でなくてもよい |
| 低 | 改善・追加要素 |

# 5. 進捗率

進捗率は以下を目安とする。

| 進捗率 | 状態 |
|---:|---|
| 0% | 未着手 |
| 25% | 作業開始 |
| 50% | 主な作業を実施中 |
| 75% | 主な作業完了・確認中 |
| 90% | レビュー・最終確認中 |
| 100% | 完了 |

厳密な工数計算ではなく、現在の作業状態を把握するための目安として利用する。

# 9. Copilotによる更新ルール

GitHub Copilot等のAIエージェントが作業する場合、本ファイルをプロジェクト進捗の正として扱う。

実装開始時：

1. 対象Task IDを確認する
2. `未着手` の場合は `進行中` へ変更する
3. 必要に応じて進捗率を更新する

実装完了時：

1. 対象タスクの実装内容を確認する
2. 必要なテストを実施する
3. テスト成功後に `完了` とする
4. 進捗率を `100%` とする

問題発見時：

1. 課題管理表へIssueを追加する
2. Issue IDを採番する
3. 本管理表の `関連Issue` にIssue IDを記載する
4. 必要に応じてタスクを `保留` とする

追加作業発見時：

既存Taskに含まれない作業が必要な場合は、新しいTask IDを採番して本表へ追加する。

# 10. Task ID採番ルール

形式：

```text
T-XXX
```

例：

```text
T-001
T-002
T-035
```

既存IDを再利用しない。

削除したタスクのIDも再利用しない。

新しいタスクは原則として現在の最大番号 + 1とする。

---

# 11. タスク削除ルール

一度登録したタスクは原則削除しない。

不要になった場合は備考へ、

```text
対応不要
仕様変更により廃止
別Taskへ統合
```

等の理由を記録する。

必要に応じてステータスを `完了` または `保留` とする。

---

# 12. 設計変更が発生した場合

実装中に設計変更が必要になった場合は、コードだけを変更しない。

以下の順序を基本とする。

```text
問題・変更要求発見
↓
課題管理表へ登録
↓
影響範囲確認
↓
該当設計書更新
↓
実装
↓
テスト
↓
プロジェクト管理表更新
↓
課題解決
```

## 12.1 コンテンツ内部リンクの管理原則

記事・用語辞典の内部リンクは、Git上のカテゴリフォルダ名やMarkdown/MDXファイル名を公開URLとして直接利用しない。

```text
Git / ファイル管理
→ カテゴリフォルダとファイル名で整理

コンテンツ識別
→ frontmatterのslugを利用

公開URL
→ /articles/{slug}
→ /glossary/{slug}

内部リンク
→ slugを基準に解決

# 14. 管理上の原則

プロジェクト管理そのものを目的にしない。

Huneyでは、

**「現在どこまで進んでいるか」**

**「次に何をすればいいか」**

**「何が問題になっているか」**

が分かることを管理表の目的とする。

管理作業が実装・記事制作の負担になりすぎないよう、必要十分な粒度を維持する。
